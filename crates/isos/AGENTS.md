# IsOS development guide

Follow the local [convention v1.3.1](docs/island/conventions.v1.3.1.md). Start with [README.md](README.md) and the [IsOS documentation](../../docs/isos/README.md). Keep English and Chinese pages aligned, give each live field one authoritative contract, and keep examples independent of package IDs.

IsOS owns the saved graph, exact package pins, local HTTP API, manager IPC, and its direct children. The package is a member of the root Cargo workspace and builds `isos`. `src/app/` parses and presents requests; `src/domain/` admits graphs, registered types, packages, and launch inputs; `src/runtime/` owns live processes, owner exchanges, and logs; `src/interfaces/` holds boundary values. The [server design](../../docs/isos/design/server.md) describes current module ownership.

Active package admission uses verified `isos.package@v1` `node_contributions`, exact pins, registered placement, declared resources, and contained file digests. IsOS does not parse package payload formats or choose behavior by package ID or executable name. The selected core owns its lifecycle adapter and descendants. The current package process handoff supports EOS; unknown owners or adapters fail explicitly. IsOS-owned HTTP routes use `/api/isos/v1/*` and `schema_version:"0.1.0"`; external owner wires retain the versions documented in their own current contracts. See the [package](../../docs/isos/interfaces/packages/README.md) and [owner](../../docs/isos/develop/owner/README.md) contracts.

`isos init --mode dev|product` creates configuration and a starter graph without launching processes. `isos serve` hosts the local workbench. Run and Restart recheck the saved revision and exact package bytes; Stop requires owner proof and IsOS child exit. Preserve strict loopback Host and Origin checks, fail closed on stale or uncertain state, and keep UI source in `ui`.

Before committing, run `cargo fmt --all -- --check`, `cargo clippy --all-targets -- -D warnings`, focused tests, and `cargo test --all-targets --no-fail-fast`. Run documentation link, JSON, and bilingual parity checks for documentation changes. Save complete output under ignored `logs/test/<run-id>/` and summarize reproducible commands in [verification](../../docs/isos/maintenance/verification.md). Use Conventional Commits. Follow the root integration branch and PR workflow; never publish a product release as part of migration work.
