# First use and qualification of the R04 native skill host

[中文](../../../docs_cn/eos/develop/host-skills_cn.md) · [ABI/selection contract](../interfaces/skills/native/host-abi.md) · [SkillService](../interfaces/skills.md) · [Rust design](../design/runtime/skills/host-rust.md) · [Cases](../../../tests/fixtures/r04_host_skills/README.md)

**Current first-use guide.** The default Rust EOS runtime implements verified native selection, confined worker, primitive Broker, seven-method SkillService and readiness; IsOS implements candidate preflight and checked retirement. `host-skill-abi-v2` is advertised by the selected binary. IsOS owns package verification, explicit selection, Validate/Apply and deployment logs. EOS owns ABI admission, per-execution worker, Broker/Dispatcher calls, SkillService and live health. The procedure below is reproducible; the observed exact merged-tip checked-retirement results and remaining live limits are recorded at the end of this guide.

1. **Prepare a clean home and package.** Build the default Rust EOS binaries and the selected IsOS binary. Author a minimal ABI v2 `.skill.so` with `eos_skill_library_query_v2`, one object parameter/result schema, one declared primitive and an instrumented `execute` handler. The minimal C fixture depends only on trusted system libc; a C++17 fixture may depend on the documented system `libstdc++`/`libgcc_s`. Do not embed RPATH/RUNPATH or package-local transitive libraries. Publish it as a P01-valid exact release and install or link it through IsOS. Record the exact receipt, release, payload and library SHA-256 values. A package install alone must not make `ListSkills` executable.
2. **Select and Apply.** On the `isos.process.component@v0.1` EOS runtime node, set `settings.skill_libraries` to one explicit `{package:{id,version},library}` entry. Validate and Apply the graph. Confirm the selected schema-2 manifest lists both `eos/graph.json` and `isos/skill-selection.json`, with matching saved `active_revision`. Confirm selected `aether-runtime --capabilities` advertises `host-skill-abi-v2`; a missing feature or changed P01 file must fail before stopping an existing child. Do not add a skill sequence node or command edge.
3. **Preflight, launch and verify readiness.** With an old run still serving, IsOS checks the candidate saved revision, selected generation, exact P01 bytes, selected runtime feature and process specs. For a nonempty skill selection it prepares candidate R03 grants and invokes the [private EOS catalog preflight](../interfaces/skills/native/host-abi.md#private-candidate-catalog-preflight) before old-child stop. Confirm one structured `ok:true` result with matching revision, generation, run ID, selection digest and ordered verified libraries, plus reaped inspection PIDs. A bad ABI, missing deployment binding or oversized public catalog must return `ok:false`, take checked candidate-grant retirement and leave the old PID, run ID, active revision and grants usable. Then IsOS rechecks inputs and starts the replacement. EOS repeats package, ABI and shared pure readiness admission on actual launch, stages fresh exact bytes and reports SkillService health `SERVING` only after every descriptor and seven R04 methods are ready. If startup fails, inspect the manager-session first failure and confirm there is no ready event or leaked worker PID. The exact merged-tip confirmed and unknown Stop replacements below qualify this checked-retirement boundary.
4. **Discover and execute.** Use the existing typed gRPC `ListSkills`/`GetSkill` identities to inspect the exact descriptor. Read `eos-active-revision` from Discover metadata. Call `StartExecution` with `authorization: Bearer <EGIA grant>`, `x-eos-active-revision: <that saved revision>`, an exact skill reference, object arguments and a stable 1–96-byte `request_id`. Store the returned `execution_id`; it is distinct from both request ID and IsOS deployment `run_id`. Follow `WatchExecution` from `after_sequence:0`, then use `GetExecution` with the same run grant after a broken watch. Confirm the declared primitive has one R03 Dispatcher journal identity and one stub-adapter call; an undeclared primitive has none. Check `ListExecutions` for the retained snapshot.
5. **Correlate logs and stop.** Find the deployment run's first ready or failure event through the IsOS cursor before filtering by execution/correlation ID. Confirm the terminal SkillExecution reason matches safe JSONL fields, without token, path, raw arguments, result or library bytes. Call `TerminateExecution` with the same EGIA grant and active revision on a running fixture. Confirm grant revocation, Dispatcher cancel/terminal or unknown outcome, bounded worker reap, then IsOS Stop. R06 separately proves simulator physical stop before termination/reap; R04 must prove its worker is gone before that sequence.
6. **Negative and restart replay.** Run every [R04 case](../../../tests/fixtures/r04_host_skills/cases.json) and [preflight case](../../../tests/fixtures/r04_host_skills/preflight_cases.json). Inject invalid ABI, missing binding and a 3 MiB list overflow after IsOS verification; each must preserve the old run. Check the four fixed IsOS preflight diagnostics for rejection, malformed output, timeout and unconfirmed cleanup. A near-90-second timeout and a candidate-grant retirement failure must keep the old process and run scope, with cleanup failure visible. Inject a library or selected-binary change after `ok:true` and confirm launch-time rejection rather than reuse of the probe result. Restart EOS within the same IsOS run to check fresh admission and Dispatcher no-replay, then start a new run to check grant rotation and old-run opacity. Record actual pass/fail and child PIDs. A static fixture is not qualification evidence.

Run `python3 tests/fixtures/r04_host_skills/check_cases.py` for fixture shape and `git diff --check` for documentation changes. The R04 qualification uses focused Rust unit and process tests, the C ABI compatibility fixture, IsOS/EOS cross-repository replay, `cargo fmt --all -- --check`, strict workspace Clippy, workspace tests and build, plus IsOS Cargo gates. Store complete command lines and output in `logs/test/<run-id>/`; summarize observed results and pinned commits here after those runs, before review and merge.

A full live 90-second timeout and post-probe executable or library mutation were not exercised in this exact-tip replay. Earlier controlled mutation and focused tests provide separate evidence. These limits remain visible for M3/M5 qualification; the R04 owner implementation and checked-retirement boundary are complete.
