The v2 Rust crates are under `crates/aether-*`: `common` supplies process-wide clock and bounded I/O primitives, `node-profile` parses and validates the unified `1.0.0` node tree, `hal` owns typed hardware values and adapters, `dispatcher` owns tree lookup and command admission, and `aether-runtime` composes them behind the `aether-runtime` API and the [Rust process](../design/runtime/process.md). C++ adapter code belongs behind the HAL CXX seam. The public `eosd` launcher now selects Rust. The C++ process remains an unlaunched side chain.

For any process that can release physical commands, use `Runtime::new_durable(profile, adapters, clock, journal_directory)` and keep the journal directory on persistent storage. Opening the directory takes an exclusive process lock. Command IDs remain reserved across restarts; unfinished records recover as uncertain, and corrupt records prevent startup. `Dispatcher::new` and `Runtime::new` keep an in-memory journal for tests. A read or malformed sample degrades the affected node; call `refresh_node` only after the adapter can provide a valid, fresh sample. A CXX driver must make `stop` independent of blocked normal operations and latch it at the physical write boundary.

## Add or change a node

1. Define the sample or command as a Rust type and document each field's type, unit, purpose, and validation in the [interface reference](../interfaces/hardware.md). Use explicit optional fields to represent unsupported observations.
2. Extend the single `1.0.0` node profile with the node's place in the `core → layer → group → node` tree, supported capabilities and modes, limits, adapter settings, and any full-path references. Reject unknown keys, missing references, duplicate paths, and malformed limits before constructing a driver. Do not introduce a second manifest or v1 profile translation.
3. Implement one C++ adapter instance per node. Keep SDK and ROS 2 types inside C++; transfer bounded, typed values across CXX. Never let a driver register its own dispatcher route.
4. Add mock-driven unit tests and an integration test that crosses the intended boundary. Exercise one healthy path, malformed input, health degradation, timeout, stop, and isolation from a second node.
5. Update both English and Chinese design and development docs, then run the focused checks and save output under `logs/test/<run-id>/`. Work on a dedicated `refactor(v2)/<topic>` milestone branch; squash merge a verified slice into `refactor(v2)/runtime-main`.

## Shared runtime primitives

Use `aether_common::time::Clock` for current monotonic time and `ManualClock` for deterministic expiry and freshness tests. Pass the clock into the HAL and dispatcher instead of reading wall time in admission code. Source timestamps may come from a ROS 2 or device clock and are for provenance; monotonic receive time is for local deadlines and freshness. Use common bounded I/O helpers at profile and adapter boundaries so an oversized file or frame is rejected before allocation or deserialization. These shared primitives keep tests reproducible and prevent each module from inventing different time or size policy.

## Compile-time shape

Keep the ordinary build independent of ROS 2 and vendor SDKs. Gate optional C++ integrations at build time so mock and core tests compile on a development machine. Use typed enums and structs at the Rust boundary and monomorphized or static paths for common operations; avoid runtime reflection and unbounded serialization on hot paths. Optimize only after a repeatable benchmark identifies a bottleneck. Preserve a mock path so optional integrations do not make the core test suite hardware-dependent.

## Cutover rule

When moving a production path from C++ to Rust, map each old operation to one typed node route, verify observation and stop behavior, and ensure only one dispatcher owns actuator release. Delete the superseded code and update old documentation in the same cutover once replacement coverage exists. Until then, label v2 behavior as foundation work and use the current runtime guides for deployed operation.
