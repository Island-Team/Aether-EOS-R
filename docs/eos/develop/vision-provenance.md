# Q01 EOS Vision owner first use

[中文](../../../docs_cn/eos/develop/vision-provenance_cn.md) · [Vision interface](../interfaces/vision.md) · [Q01 program](../../island/implementation-todo.md)

This guide covers the EOS side of an IsOS-selected camera-to-EGIA evidence binding. IsOS owns the saved graph, run directory, selected gate, verifier and grants. The EOS runtime only reads the applied projection; its HTTP bridge adds an owner-only Unix listener while retaining the public loopback Vision endpoint.

1. Select one active `eos.interface.camera_gate@v0.1` in IsOS `[vision_evidence].gate_path`. The selected source must be a registered `eos.hardware.camera@v0.1` with an admitted EOS-local `frame:camera_frame` route. Validate and Apply the saved graph. A graph-authored `service_bridge` edge is invalid.
2. Inspect the selected EOS binaries with `aether-runtime --capabilities` and `aether-http-bridge --capabilities`. They must advertise `vision-provenance-v1` and `vision-owner-uds-v1`, respectively. IsOS rechecks exact executable and package bytes before replacing a running deployment.
3. Start the managed EOS runtime through IsOS. On its private runtime socket, `{"op":"vision_attest","gate_path":"<selected gate>"}` reports the IsOS saved `active_revision`, the EOS `projection_revision`, the deployment `run_id`, a fresh `runtime_stream_id`, source and gate paths, and `gate_generation:0` before the first delivery. It returns unavailable when the selected gate is unhealthy or EOS is stopping. The standalone runtime cannot claim managed provenance.
4. IsOS starts the same `aether-http-bridge` process with its public `--listen`, private EOS `--socket`, `--run-id`, and `--owner-vision-socket <endpoint-dir>/eos-vision-owner.sock`. It supplies only `AETHER_BRIDGE_VISION_VERIFIER_FILE` to that bridge. The verifier is a 0600 owner file beside the socket in a 0700 private endpoint directory and contains the SHA-256 of the decoded 32-byte EGIA Vision grant, not the grant. IsOS keeps the grant and binding in the control-grant run directory. The owner listener is 0600 and accepts only same-UID UDS peers with `Host: localhost`, no Origin or Sec-Fetch header, and the exact bearer grant. Public TCP requests carrying Authorization are denied.
   For a managed replay, read `egia/vision-binding.json` and the grants from the control-grant run directory. Connect to the absolute `eos_endpoint.path` in that binding. Its parent is the IsOS-selected `run/v/<32-hex>` directory; derive the EGIA inspection and optional one-shot stale-test sockets as siblings. The replay checks the endpoint digest against the deployment and run ID before connecting.
5. The EGIA subscriber uses `GET /api/eos/v2/vision/owner-ws`, then sends one masked `subscribe` frame with the selected gate, EOS projection revision, `target_fps:30`, `max_width_px:1280`, and `jpeg_quality:80`. A reconnect may pass both `after_generation` and `after_runtime_stream_id`; an old stream is refused. A successful `subscribed` text frame precedes every binary frame. Binary metadata and JPEG are bounded to 4096 and 8 MiB bytes, respectively. Check the delivered `(graph_revision,runtime_stream_id,gate_path,gate_generation)`, source frame ID and SHA-256 of the exact JPEG bytes. The browser and EGIA receive the same canonical JPEG only when both request the fixed render.
6. Inspect `route_status` for `cap_wait_count`, `replaced_count`, and `gap_count`. Stop through IsOS and confirm its existing actuator stop precedes MuJoCo termination. EOS seals Vision publication before that stop; the bridge closes owner subscriptions and removes the run socket when stopped. It rereads the private verifier and ready attestation on each bounded owner poll, so revocation ends an established subscription before another JPEG. A new EOS child rotates `runtime_stream_id`; a new IsOS run also rotates its Vision grant.

For a focused local check, run `cargo test -p aether-http-bridge --bin aether-http-bridge`, `cargo test -p aether-runtime --test process managed_gate_attests_saved_and_projection_revisions_and_exact_jpeg`, and `cargo fmt --all -- --check`. These tests cover the EOS boundary; they do not by themselves qualify the cross-owner Q01 replay. The full selected-pin replay and its tamper cases are recorded in the Q01 qualification evidence after all owners implement their bindings.
