# Inspect EOS evidence routes

[中文](../../../docs_cn/eos/usage/routed-edges_cn.md) · [First use](README.md) · [Owner contract](../interfaces/hardware.md#r01-live-eos-local-evidence-routes--target-contract)

**R01 implemented in this topic branch.** IsOS owns graph admission and Apply. EOS delivers admitted local camera evidence through per-gate routes. The owner socket exposes `route_status` for the current runtime generation.

First install and verify the required package, select the camera and gate in the IsOS graph, then Validate and Apply the graph as described in [first use](README.md). The [G06 evidence fixture](../../../tests/fixtures/edge_contract/valid_evidence.json) shows the exact `@v0.1` camera frame connected to the gate frame with `priority:-20` and `frequency_hz:15.0`. IsOS rejects QoS on fixed actuator, safety, result, health and stop paths before Apply. A successful Apply only admits the declaration; it does not prove that a camera is healthy or a frame was delivered.

Launch the deployment and inspect authoritative IsOS status and the current run before reading an EOS route. The owner-only runtime Unix socket accepts `{"op":"route_status"}` from the local owner. Find the socket from the active deployment, not an old graph revision. The response's `projection_sha256` identifies EOS's projection bytes. For the fixture route, expect `delivery_state:"active"`, `routed:true`, `priority:-20`, `frequency_hz:15.0`, `weight:40`, and `queue_class:"latest"`. A configured but unimplemented EOS-local edge returns `not_routed` with null scheduling fields; a fixed governed path returns `fixed_not_scheduled`. The legacy EGIA guard → EOS Dispatcher cross-core design declaration is omitted from EOS status and remains visible through IsOS graph inspection. Neither a row nor its absence implies hardware health. The route counters show delivery and gaps; an empty queue or zero delivered count is not itself a readiness failure.

To inspect an overload, compare `delivered_count`, `cap_wait_count`, `replaced_count`, `overflow_count`, `consumer_error_count`, `cancelled_count`, and `gap_count` within one runtime generation. A rate cap can increase waiting without loss. A new image replacing a retained image increases replacement and gap counts. Stop closes evidence admission, invokes Dispatcher emergency stop before waiting on evidence workers, and cancels pending evidence with a gap. The owner socket no longer serves `route_status` during or after shutdown; inspect counters before stopping and use IsOS status and run events afterward. Command results, health, and stop come from their existing owners and remain outside these queues. Use IsOS run-bound logs to find the first ready or failure event, then correlate with owner status; do not infer health from a route row. A restarted runtime resets counters; use IsOS run and process identity to distinguish generations even if the projection digest is unchanged.

If the route is `not_routed`, check the exact source and target type IDs, ports, data type and transport against the [contract](../interfaces/hardware.md#r01-live-eos-local-evidence-routes--target-contract). Similar or contributed identities do not gain delivery. If startup rejects a missing compiled endpoint or too many live routes, use IsOS's owner-reported failure and keep the saved graph unchanged while correcting it. [Scheduler design](../design/runtime/scheduler.md) explains the bounded queue and fairness rules.
