# R04 Rust native skill host

[中文](../../../../../docs_cn/eos/design/runtime/skills/host-rust_cn.md) · [Owner ABI and selection contract](../../../interfaces/skills/native/host-abi.md) · [SkillService](../../../interfaces/skills.md) · [First use](../../../develop/host-skills.md) · [Cases](../../../../../tests/fixtures/r04_host_skills/README.md)

**Implementation status.** The default Rust runtime implements R04 verified selection, the confined native worker, a bounded execution manager, primitive Broker, seven-method SkillService and readiness admission. It advertises `host-skill-abi-v2`. IsOS implements pre-stop candidate preflight and checked grant retirement. Exact merged-tip live replacement confirmed old Stop and fail-closed unknown Stop; the full live 90-second timeout and post-probe executable/library mutation remain outside that replay. The opt-in C++ `src/eos/runtime/skills/` manager and worker remain for Q02 last-caller review. The historical graph-authored sequence helper in `crates/aether-runtime/src/bin/aether-runtime/skills.rs` has no deployed managed `skill_execute`, `skill_result` or `skill_cancel` route. The R04 host catalog and SkillService do not call that helper. R03 supplies run-scoped grants, active revision and durable Dispatcher; IsOS supplies exact package verification and the selected manifest.

## Startup barrier

1. IsOS validates the explicit `settings.skill_libraries` graph declaration, P01 receipt and library bytes, renders `isos/skill-selection.json`, and requires `host-skill-abi-v2` from the actual selected `aether-runtime` before stopping any prior child.
2. EOS validates its R03 selected profile and grant verifier, then the same selected manifest's sole `isos/skill-selection.json` entry. A partial handoff is an error. An absent selection is an empty, nonexecutable catalog.
3. For each selected entry EOS validates the receipt, release, payload tree, exact library digest and safe path. It opens the library without following links and stages those exact verified bytes in an owner-only read-only file. It parses the ELF dependency table and rejects RPATH/RUNPATH or any package-local/unlisted transitive library; only the [owner contract's trusted system SONAMEs](../../../interfaces/skills/native/host-abi.md) may resolve. Only data is parsed in the parent; it never loads package code.
4. EOS re-execs the selected `aether-runtime` in private `--skill-worker` inspection mode with one inherited `SOCK_SEQPACKET` channel and one staged file. The child establishes required `no_new_privs`, resource limits, Landlock and seccomp policy before `dlopen`, then queries `eos_skill_library_query_v2(2)`. Enforcement failure prevents load. Constructors and query code may execute inside this confined worker; the `execute` handler is never called for an invalid descriptor. This is a confinement and fail-closed admission seam, not a general containment proof.
5. The parent validates bounded descriptor data and all selected libraries as one catalog transaction. Only then does it bind public SkillService and report ready. A failed candidate is fully reaped before this EOS child reports ready. The implemented [private candidate preflight](../../../interfaces/skills/native/host-abi.md#private-candidate-catalog-preflight) moves the same catalog inspection before IsOS stops an old generation; that cross-owner behavior is implemented and its checked-retirement boundary has exact merged-tip live evidence. Do not reuse the C++ loader's recursive directory scan.

## Candidate inspection before replacement

The private EOS command, shared static validator, IsOS pre-stop call and checked candidate-grant retirement are implemented. The exact merged-tip confirmed and unknown Stop replacement replay is recorded in the [first-use guide](../../../develop/host-skills.md#exact-merged-tip-r04-checked-retirement-qualification-2026-11-02).

The IsOS `restart_processes_with_plan` path allocates a candidate run while preserving the old supervisor, completes P01/P04/P05/spec checks and invokes the selected EOS `--skill-catalog-preflight` with candidate run ID, generated profile, node contributions, selection file and verifier. It does not publish the candidate run before the old Stop is confirmed. Failure takes checked candidate-grant retirement and retains the old run when retirement is confirmed; uncertain retirement is surfaced as a typed failure. After a successful probe, IsOS rechecks inputs, confirms the old R06 Stop, then publishes and launches the candidate. The owner contract defines exact invocation, JSON result, bounds and error precedence.

Preflight enters a restricted path before normal runtime construction. It loads the managed verifier and profile data, calls the same selected catalog admission and a shared pure readiness validator used by startup. That validator extracts the current `Catalog::validate_broker_coverage` and `HostSkillManager::new` checks: declared callback coverage, public descriptor projection and encoded 3 MiB `ListSkillsResponse`, plus a static binding for each declared primitive from `admitted_bindings(profile)` and the projection's profile-level eligibility rules. Live terminal-stop-fence, adapter and health checks still happen at launch and invocation. Its mode cannot bind IPC/gRPC, construct Runtime, Projection, adapters or Dispatcher, open a journal, launch MuJoCo, accept a SkillService call or invoke a guest handler. The parent parses only bounded, copied worker metadata; constructor/query code remains confined. It exits after every confined inspection child and staged file is gone. IsOS applies a hard global 90-second deadline to the whole probe; this may reject a near-limit but valid package. Timeout or uncertain inspection-child reap fails before old stop. This leaves R05's delayed physical release and R06's stop order as separate gates. Unit tests for the extracted validator must cover missing base/arm binding, unavailable declared callback, exactly-at/over 3 MiB public encoding and parity between preflight and startup on the same valid profile.

The probe checks a snapshot, not a reservation. IsOS compares its structured result with the selected generation and revalidates saved graph bytes, manifest inventory, selected executable, candidate verifier and all P01 inputs immediately before replacement. A failed post-probe check also takes checked candidate-grant retirement. New EOS startup independently reopens and stages those files and repeats ABI and pure readiness admission before ready, so a mutation after the probe fails closed and follows existing candidate recovery. Automatic child restart within one run repeats startup admission against the same selected generation. Tests must prove a bad ABI or missing binding leaves the old process and grant usable, a near-boundary timeout cleans up without stopping it, and a post-probe library swap is refused at launch.

The private worker uses a versioned bounded packet envelope, `SO_PEERCRED` for the launched peer, and no public listener or inherited hardware socket. A protocol, peer or size mismatch rejects the session. The C ABI remains frozen; the internal Rust worker protocol is EOS-build-private and may change without changing the public ABI. The worker and parent share no package pointers. The worker cannot acquire a runtime, Dispatcher, device, graph-edit or workflow handle. A descriptor has no grant during inspection.

## Invocation and broker

The Rust SkillService facade implements `ListSkills`, `GetSkill`, `StartExecution`, `GetExecution`, `WatchExecution`, `ListExecutions`, and `TerminateExecution` from the published `island.eos.v1` proto. All other methods retain the proto identity and return `UNIMPLEMENTED` until reviewed parity work. List/Get expose a sorted immutable admitted descriptor set. Start validates exact identity, object schema, request ID, optional timeout, R03 EGIA grant and active revision, reserves one idempotent execution, and starts one confined worker when a slot is available. A descriptor declaring claims fails catalog admission until a Rust claim scheduler exists; R04 never publishes unenforced claim templates. Non-reentrant descriptors serialize by exact `{name,version}` in FIFO start order, with queued deadline and cancellation before worker launch. One active execution receives a bounded broker grant for each exact declared primitive and resolved admitted binding. The guest receives only ABI callbacks; host callbacks traverse private IPC and the broker. Missing optional ABI callbacks are `NULL` and report unavailable by the ABI rules.

The broker's primitive request must match the admitted descriptor, exact primitive/version, resolved device, execution, generation and deadline. It derives a private 67-byte command ID from the IsOS `run_id`, exact skill identity, public Start `request_id` and primitive-call index using the [owner contract's domain-separated hash](../../../interfaces/skills/native/host-abi.md), then enters the R03 Dispatcher with server-attested `skill-worker` ingress and the start's authorized role. The same run derives the same ID across EOS child restart; a new run derives another ID. Dispatcher rechecks active revision, health, observation, limits, journal and safety at physical release. A broker token is internal and never appears in public protos, worker logs or package data. No worker IPC packet can directly issue a raw adapter call. R04 requires the primitive path. A descriptor with resource, inference, source, SIGNAL or community declarations fails atomic catalog admission until that callback family has a complete Rust owner. The host may leave optional callbacks `NULL` for undeclared families, including log/checkpoint callbacks whose availability is checked at use. Child-process callbacks are not bridged in 0.x.

Execution records are process-local and bounded. A retained identical `request_id` returns the original `execution_id` and snapshot; a conflicting reuse fails without a worker. If the process restarts, the execution table is not replayed as a new guest invocation. Dispatcher journal identity still prevents an uncertain released command from being issued again under the same derived ID. Start and worker response bodies are schema-validated, bounded and sanitized before publication. `WatchExecution` follows lifecycle sequence; a disconnect drops only the watcher. Worker exits, terminal result and claim release happen once.

## Cancellation, failure and observability

Termination of one execution closes its broker admission, revokes grants, cancels active Dispatcher command IDs, waits a bounded interval for terminal or uncertain results, then signals, terminates if needed and reaps the worker. EOS projects an unresolved actuator as `EXECUTION_STATUS_FAILED` with `reason_code = "worker.outcome_unknown"`; it does not turn that into success or retry it. A queued execution can cancel without spawning. Whole-runtime shutdown follows the stronger safety order: `grpc_server.begin_shutdown` and host intake close first; `dispatcher.quiesce` seals new movement; the existing `stop_guard.stop` issues admitted actuator stop immediately, before waiting on any skill worker. Then the host broker revokes grants, cancels remaining command IDs through the still-available Dispatcher cancellation seam, and boundedly reaps workers while the simulator child remains alive. The legacy `skills.shutdown` has no deployed managed work and cannot hold the stop path. Only after host workers are reaped or an explicit stop failure is recorded may R06 terminate/reap MuJoCo with `drop(backend)`; a failed physical stop cannot be reported as safe. A timed-out worker must remain explicitly unreaped/failing until the OS child is actually reaped; no completed-stop event may claim otherwise. The blocked-worker fixture currently proves bounded `TerminateExecution` and worker reap; a process-level stop-order test with a simulator child remains an R06 integration gate. R04 cancellation can still race a Dispatcher command already in `Releasing`: it records `OUTCOME_UNKNOWN` and preserves movement inhibit. The terminal physical fence for an adapter move delayed past stop is an R05/R06 boundary and must be proven there before claiming simulator safe-stop.

Use the shared JSONL event envelope with deployment `run_id`, execution/correlation ID, safe package pin, stage, reason code and worker reap result. No package path, raw descriptor, arguments, result body, credential, token or library bytes enter the event. P07 log rotation must preserve the first failure or ready event after IsOS admits these codes. The [frozen R04 cases](../../../../../tests/fixtures/r04_host_skills/cases.json) distinguish pre-worker data rejection, confined query rejection, guest-handler refusal, broker denial, uncertain physical outcome, and bounded cleanup. C ABI old-prefix and optional-tail fixtures compare exact C layout and query symbol against the existing opt-in implementation. Full outputs belong under `logs/test/<run-id>/` before R04 closes.

The selected C guest fixture uses a build-metadata P01 pin and an actual host event sink to verify bounded lifecycle JSONL. IsOS now admits `eos_skill_execution` and `eos_skill_stop_unconfirmed` in its closed child-event policy. The exact merged-tip replay retained the first ready and unknown Stop failure through a harness-induced log rotation; it does not show automatic size-threshold rotation.

Worker spawn, IPC and protocol failures are mapped to fixed public `worker.failed` or `worker.protocol_invalid` reasons before `SkillExecution` and JSONL publication. Internal `HostError` strings and guest-provided failure text are never copied into the public lifecycle event. This keeps the IsOS child-event policy over the reviewed `worker.*` namespace.

A post-spawn invocation send failure is not treated as a pre-worker error. `Catalog::start_worker` explicitly attempts terminate/reap and returns the observed reap state to the manager. `Some(false)` keeps the worker slot and nonreentrant lane occupied and makes `wait_stopped` fail. The selected C fixture exercises a real post-spawn invalid invocation with confirmed reap; a manager unit fixture injects the unreaped outcome and proves the stop cannot pass.

Inspection startup applies the same cleanup rule. A failed Inspect send and a failed `pidfd_open` have bounded reap attempts; unreaped inspection children produce a specific `eos_skill_stop_unconfirmed` startup event and block ready/backend launch. The negative helper test freezes the transport-error versus unreaped-error precedence. It does not simulate a kernel uninterruptible child.
