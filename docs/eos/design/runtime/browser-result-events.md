# Q01 browser command event design

The existing P06 sink permanently disables writes after a nonblocking error. The bridge does not retry a lost diagnostic in the same process or change the command response; Q01 full verification fails if its selected correlated line is absent.

[中文](../../../../docs_cn/eos/design/runtime/browser-result-events_cn.md) · [Owner event contract](../../interfaces/events.md#q01-browser-command-correlation--eos-producer-implemented) · [Browser result contract](../../interfaces/control.md#r07-authorized-browser-result) · [Cross-repository task](../../../island/implementation-todo.md)

**EOS producer implemented; selected IsOS admission and Q01 replay pending.** The bridge forwards typed browser control and authorized result follow-up to private runtime IPC, validates successful private result identity and status, and emits a sanitized event. IsOS's closed P06 bridge role still admits only lifecycle events on the current remote pin. The Q01 replay therefore cannot yet find the UI command ID in P07 current-run logs.

The bridge preserves the published 128-byte UTF-8 browser ID acceptance. It uses the exact command ID as P06 correlation when safe and a deterministic opaque token for other valid IDs, so existing same-run follow-up remains possible without logging arbitrary text. After a private response, it emits a result event only when `ok` is true, the result ID equals the request ID, and the status is in the published Dispatcher enum. It does not derive status from HTTP 200 or a request body. A bounded 1024-entry status cache suppresses repeated `InProgress` polls and terminal reads while retaining submit and first observed terminal transitions. The shared nonblocking event sink serializes bounded writes from client threads; a failed write is diagnostic loss, never command failure or a reason to replay movement. The [owner event contract](../../interfaces/events.md#q01-browser-command-correlation--eos-producer-implemented) defines the token mapping, every field, and the safe response boundary.

Boundary tests use a private runtime stub for immediate terminal, `InProgress` then `Completed`, wrong ID/status, missing grant, same-run 128-byte/non-ASCII IDs, duplicate follow-up, sustained polling, cache eviction, concurrent calls, and sink failure. Selected-pin integration compares the raw bridge event with IsOS's normalized line, P07 page, UI-visible ID and one EOS journal outcome. The log proves correlation and admission of a sanitized owner event; the journal remains outcome authority.
