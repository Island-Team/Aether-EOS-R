# Rust EOS event producer — P06

[中文](../../../../docs_cn/eos/design/runtime/events_cn.md) · [event contract](../../interfaces/events.md) · [foundation](foundation.md)

The [EOS JSONL contract](../../interfaces/events.md) defines the wire fields. IsOS owns the log store and preserves structured child stderr. The shared `aether-common::events::EventSink` owns validation, UTC serialization, fixed event constructors, monotonic duplicate suppression and one synchronized stderr writer for `aether-runtime`, `aether-http-bridge` and `aether-config-server`. The strict public envelope is serialized directly from those constructors; a generic `tracing-subscriber` formatter is not attached to stderr because it would admit extra keys and arbitrary span or error text. Internal tracing can use a separate facade without changing the wire sink. The sink never takes arbitrary `serde_json::Value`, a `Debug` span or an error's `Display` output as a message. The control protocol and `--capabilities` stdout remain separate.

The current `aether-runtime` parses `--log-dir` but uses it only to capture the direct MuJoCo child's stdout/stderr into `mujoco.log`. On managed launch IsOS supplies the private `data/logs/<deployment>/owner/eos/` directory; this raw diagnostic file is separate from IsOS-owned top-level `eos.log` and `events.log` and is not reclassified as a shared EOS event. Its `StopGuard` calls dispatcher emergency stop before `BackendChild` is dropped and reaped. P06 adds `--run-id` parsing to runtime, bridge and config server, initializes the stderr emitter after argument admission, and emits one process startup event. A parse failure before an emitter exists remains a fixed sanitized exit diagnostic for IsOS to record with its manager-session ID. Runtime emits `eos_ready` after profile, node registry, adapter/journal, backend socket and control socket admission, beside the existing stdout ready line. Bridge emits `bridge_ready` after its listener binds; this means its local HTTP transport is listening and does not claim EOS upstream or whole-deployment readiness. Config server emits `config_ready` after its profile/catalog is validated and listener binds. IsOS status remains authoritative for overall deployment readiness.

The MuJoCo process is still EOS's direct child. On a managed launch, IsOS rechecks the schema-2 receipt and passes the paired release/payload digest options with the already supplied backend node/executable/scene. EOS validates those options and checks the exact graph package pin, then emits one package provenance event. It expands the validated four-segment `--backend-node` identity to the saved-graph JSON Pointer, escaping each segment per RFC 6901, and never emits the internal short path. Standalone/manual launch may omit the pair and produces a provenance-unavailable warning without altering launch behavior. EOS never parses or logs child stdout, scene XML, absolute paths, arbitrary environment or backend error text as an EOS event. The private MuJoCo raw capture path handles its child stream; P06 EOS records only typed transitions and fixed reason codes. A changed receipt before launch is an IsOS prelaunch failure, not an EOS run event.

Startup failure after event initialization emits one terminal `*_start_failed` with a fixed `stage` and `reason_code`; no `*_ready` is emitted. The backend liveness check emits `eos_backend_lost` once on its transition to lost and then exits through the existing guard order. On graceful signal, log `eos_stopping`, close command admission, wait for bounded emergency stop results, log `eos_stop_unconfirmed` for each unconfirmed target, then terminate/reap the simulator and emit `eos_stopped` only when shutdown actually completes. A sudden kill leaves no fabricated terminal EOS line; IsOS's supervisor records the observed exit. The journal's durable `Prepared`, `Releasing` and `Terminal` phases are authoritative for command recovery. P06 events must not reinterpret an uncertain command as Completed.

High-rate producer paths do not format events: Vision frames, observation polls, dispatcher release loops and the backend socket poll emit nothing per iteration. A non-real-time transition handler emits once; repeated nonterminal warnings use a fixed-capacity 256-key table and five-second monotonic window. The first occurrence is always written, including when the table is full; the oldest key is evicted and its suppressed count can be summarized. The producer only suppresses the registered `eos_package_provenance_unavailable` warning. Terminal, safety and readiness records bypass suppression. Event construction caps every scalar and the encoded raw line at 4096 bytes including newline, within the contract's 8064-byte maximum. A single nonblocking stderr write prevents a full collector pipe from delaying emergency stop or child reap; a failed or partial write disables later writes so another record cannot extend a damaged line. IsOS adds only its observed child PID to the stored envelope within 8192 bytes. The emitter never writes a PID. Log success is never a readiness or physical-stop check. The private MuJoCo raw-copy loop retains at most 8192 bytes of an unterminated child line while draining the remainder, then continues with following lines.

Implementation tests should use a fake clock and captured stderr: each process emits one startup and at most one ready; failure before ready has no ready; managed run IDs match across EOS/bridge/config; package event has exact pin and both P01 digests; standalone package warning has no invented digest; thousands of repeated errors produce bounded summaries without losing a terminal failure; raw frame, prompt, secret, path and MuJoCo stdout never appear. A stub backend must prove the current stop-before-reap order and an uncertain dispatcher result remains uncertain. The [frozen fixture](../../../../tests/fixtures/jsonl_events/README.md) records these cases. Run Cargo fmt, strict workspace Clippy, focused/integration tests and a clean-home IsOS capture replay with full local logs before the implementation PR.

JSON parsing, relative-link checks and `git diff --check` pass. `cargo fmt --all -- --check`, `cargo clippy --workspace --all-targets -- -D warnings`, `cargo test --workspace` and `cargo build --workspace` pass on the unchanged Rust implementation. These are design checks, not P06 runtime qualification.

The process replay covers managed and standalone backend provenance, backend loss, private child output, startup failure, probe stdout, exact raw envelope, correlation, stop-before-reap, a full unread stderr pipe and raw secret/error redaction. IsOS capture/replay and final integrated first-use qualification remain cross-repository gates.
