Q01 is merged at EOS integration commit `65475f56389d8fc6d0e21d15300fb3206dedbdc1`. Q02 works on a focused topic branch from that commit. The [cross-repository TODO](../../../island/implementation-todo.md) assigns Q02 to EOS after Q01; Q03 owns the later full release gates.

The removal order follows CMake dependencies from public roots. First correct the default install's nonexistent `*-v2.md` page inputs and make contract/schema installation independent of the old C++ process switch. Extract the active skill SDK target, headers, package files, shared skill examples and SDK tests into a narrow build path. Then assess old uninstalled process entries (`adapters/eos-cxx/bin`) one by one against Rust parity. The opt-in C++ north HTTP server stays while its published `/v1/eos/*` and `/v2/eos/*` REST, SSE and WebSocket routes are supported; the Rust `/api/eos/v2/*` browser bridge has a different contract. Removing that server requires route-level equivalent implementation and tests, or a separately reviewed deprecation that updates both HTTP contracts, launcher/install expectations, OpenAPI status and tests. `EOS_NORTH_HTTP` and `EOS_REPL` CMake option interactions must be checked explicitly. Keep the physical ROS/vendor side chain buildable; the Rust MuJoCo child does not prove physical driver parity.

The old `adapters/eos-cxx/runtime/skills/native/sdk_support.cpp` is an active SDK source even though its directory also contains old runtime code. Preserve the exact SDK CMake target names, `.so.2` SONAME, package paths and exported symbols during extraction. The old `tests/eos/CMakeLists.txt` mixes C++ integration tests with active contract, doc, wrapper and SDK checks. Both must be split before deleting old process libraries. The published `share/eos/contracts/eos/`, `share/eos/schemas/eos/` and OpenAPI data are product resources, independent of native C++ protobuf generation. Historical Workflow/ActionList, model and skill engines have no Rust parity and remain if a component-level contract or active caller exists. A no-caller, no-contract implementation detail may be deleted only after an explicit inventory proof and independent exception review. No directory is deleted from a broad category row.

Rename live `v2` example and script filenames in a separate mechanical commit after enumerating `include_str!`, runtime paths, CMake install lists, fixtures and English/Chinese links. Preserve bytes of the historical `1.0.0` MuJoCo example. Do not rename `v2` wire routes, protobuf identities, ABI names, socket protocol, generated snapshot layout or historical release tags.

Before each deletion, update the inventory for each target and source with its last compiled, installed, runtime, test and documentation caller, exact Rust parity command/result or reviewed no-contract exception, and final disposition. Directory deletion is blocked until every contained component has such a record. Resolve `bin/island-launch` as a separate active-caller decision. Test the default Rust build and temporary-prefix install, installed wrappers, skill SDK package and symbol table, schema/manifest/OpenAPI checks, EGIA typed import, HAL CXX mock, adapter-host failures and stop, Dispatcher/journal, gRPC, browser bridge and process paths. If north HTTP is retained, test its published REST/SSE/WebSocket routes directly; a resource-only OpenAPI check cannot claim server behavior. Configure, build and CTest the reduced opt-in C++ side chain. Correct `docs/eos/develop/README.md` and its Chinese pair on active proto/schema ownership, `docs/eos/develop/build-and-run.md` and its Chinese pair on merged R05 strict readiness, and `docs/eos/design/runtime/foundation.md` and its Chinese pair on current host skill loading or dated MVP history. Check bilingual HTTP route wording and all links. Save full output under `logs/test/<run-id>/`, obtain independent implementation review, and squash merge Q02 into `refactor(v2)/runtime-main` only after gates pass.
