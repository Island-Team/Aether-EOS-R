## Disposition

The default install now publishes the existing bilingual guides in sibling `docs/` and `docs_cn/` directories, EOS contracts and schemas independently of `ISLAND_BUILD_EOS_CPP`. The native skill SDK can build and install with the old process disabled; its target names, ABI and sample remain. Its installed package includes fetched nlohmann JSON headers when no system package exists, and the external consumer test uses only that installed prefix. Live `v2`-named backend profiles and the workspace test script have topic names, with graph bytes unchanged. Public launchers still select the five Rust executables.

The exact reverse-caller audit did **not** authorize deleting native `eosd`, native `eos-config`, north HTTP, native REPL, physical adapters, or entire C++ runtime directories. Native `eosd` is the only executable composing the historical WorkflowService; the published old HTTP workflow routes remain a caller and have no Rust route parity. Native `eos-config` has a directly tested JSON setup contract that differs from the Rust profile launcher. The native REPL's documented HTTP/SSE commands exceed the Rust TUI. Physical ROS/vendor behavior is outside this 0.x parity scope. The component-level dispositions and retained ABI/schema resources are in the inventory. No source was deleted merely because its default build option is off.
