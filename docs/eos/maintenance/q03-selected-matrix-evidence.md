The build input maps must cover every tracked file under `src/`, `public/`, and `scripts/`, plus the package, lock, Webpack, and TypeScript configuration files.

The full verifier requires `--expect-selection`, `--expect-selection-sha256`, `--expect-build-receipt`, `--expect-build-receipt-sha256`, `--expect-case-receipt`, `--expect-case-receipt-sha256`, and all five `--expect-<owner>` commits for the selected profile. The verifier compares every applicable case IsOS, EOS, and EGIA executable with the main receipt, compares retained package assets with the main receipt, and checks every case-specific UI file against the external case receipt. A new five-commit tuple without the external files is rejected. The old five-flag invocation is accepted only for the historical tuple. `--main-only` remains an incomplete diagnostic. A checksum reseal does not authorize new evidence.

The selected main replay builds `dist/local` and `dist/hosted` separately. It records HTTP byte hashes for the actually served local index and scripts and for hosted `/en/isos` and `/cn/isos`, with hosted assets served under `/isosui/`. During the browser pause, `tests/q03_browser_capture.py --archive <live-output> --selection <external-selection> --expect-selection-sha256 <digest>` starts a local recording HTTP proxy before Firefox navigation. It retains the initial navigation and all observed JavaScript/CSS response URL, status, and base64 bytes actually delivered to Firefox for `local`, `hosted.en`, and `hosted.cn`, through Graph and Control navigation and the local Vision panel opening. The capture waits for the resource set to settle and retains browser navigation timing, resource timing, `document.scripts`, and raw editor DOM. It explicitly fetches each build's `manifest.json` in the browser and retains both the browser body and intercepted response. The offline verifier matches browser resource URLs to intercepted responses, checks their bytes against the selected build receipt, and checks manifest schema, version, selected UI commit and target. Current Webpack JavaScript embeds CSS through `style-loader`; external CSS responses are checked if observed. The proxy retains only approved index, JS, CSS and manifest bodies; it does not archive unrelated owner API response bodies.

The hosted browser capture is a **simulated hosted-Origin check** because the selected hosted pages are served from a loopback test server. For requests whose exact Origin is that test server, the recording proxy substitutes `https://os-island.com` only toward the selected IsOS and EOS bridge ports and their `/api/isos/v1/` and `/api/eos/v2/` routes. It returns the synthetic Origin in `Access-Control-Allow-Origin` only when the raw upstream header exactly approves `https://os-island.com`; it preserves the raw status. `q03-simulated-hosted-origin.json` records original and forwarded Origin, raw and delivered status and CORS headers for each translated request, as well as direct unmodified IsOS GET and EOS preflight 403 responses to the synthetic Origin. This is test proxy behavior, not a production CORS policy change or proof of a public-domain deployment.

The selected replay requires this record before accepting the browser pause release. The offline verifier checks its exact ports, API routes, Origin mapping, approved raw CORS header, unchanged successful status, IsOS GET and EOS Control **POST preflight with `content-type`**, raw methods and headers permitting that request, and both direct 403 checks. If Control navigation did not produce that preflight, the capture issues a browser-origin `POST {"op":"time"}` through the proxy and requires its preflight; it records whether navigation or the explicit browser probe supplied the observation. It matches `q03-hosted-origin-validation.json` to the record digest and proof, the archive checksum manifest includes both files, and the reviewer-owned case receipt freezes the record digest. Missing or contradictory records fail even after a local checksum reseal.
