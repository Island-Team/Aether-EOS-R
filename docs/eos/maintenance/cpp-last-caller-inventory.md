## 2026-11-04 cleanup verification

The sole code deletion in this round was the empty `eos_skills_external` target above. `cargo fmt --all -- --check`, `cargo clippy --workspace --all-targets -- -D warnings`, `cargo test --workspace -- --test-threads=1`, `cmake -S . -B build/eos-cleanup -DISLAND_BUILD_EOS_CPP=ON -DISLAND_BUILD_TESTS=ON -DEOS_NORTH_HTTP=OFF -DPython3_EXECUTABLE=<repo>/.venv/bin/python`, `cmake --build build/eos-cleanup -j4`, `ctest --test-dir build/eos-cleanup --output-on-failure -j4` (65/65), staged `DESTDIR` install and `python3 scripts/check_doc_links.py --all` (356/356) passed. Complete output is under ignored `logs/test/20261104-eos-legacy-doc-alignment/`. The first parallel workspace test run had one managed-stop timing failure; the isolated case and serial full workspace rerun passed. The first CMake attempt used system Python without protobuf; the configured repository Python resolved that dependency.

Against the five merged owner heads, focused clean-home M2 cases 01 (package install), 08 (Apply, generated-input rejection and Run), 12 (ready state and events), and 22 (Stop and log event) passed with exact-head and binary digests in the same log directory. The initial 08 run rejected a symlinked generated binary input; it passed after staging regular executable files, as recorded in the rerun transcript. This was a focused replay, not the full frozen M2 gate. Historical cases 13 and 18 did not pass: 13 expects EGIA to reject a graph the current reader accepts, and 18 expects an older exact manager failure string after repeated child loss. Their transcripts are retained; neither is counted as current qualification evidence. The `1.0.0` byte-preserving migration and refusal paths remain covered by the current IsOS suite and the retained EOS compatibility fixtures.
