# Q03 EGIA qualification design

[中文](../../../docs_cn/ei/design/q03-qualification.md) · [Stage interface](../interfaces/pipeline.md) · [Vision interface](../interfaces/vision-evidence.md) · [First use](../develop/build-and-run.md)

This is the EGIA owner design for EOS milestone Q03 and EGIA E5. It defines the qualification evidence, not a new runtime interface. The EGIA owner evidence includes the merged [installed/benchmark slice #103](../../island/retired-repository-references.md#ref-bd5748ad94f4), [selected replay documentation #104](../../island/retired-repository-references.md#ref-df85274ba886), exact selected-head CI, the sealed cross-owner Q01 replay, and the installed-prefix managed-process receipt below. The installed-process E5 evidence boundary has passed independent review. Cross-owner Q03 closure still needs exact-head reconciliation with EOS's source gate; Q04 release qualification and tags are separate.

## Selected-run prerequisites

Pin the exact merged IsOS, EOS, MuJoCo `island/mujoco-sim@0.1.1`, and EGIA commits, package receipts, dependency-lock digest, saved graph revision, EOS projection revision, and selected `egia/stages.json` revision. Record the actual remote integration-branch state. The Q01 archive must include one clean-home IsOS → Rust EOS gRPC → MuJoCo → EGIA run, selected camera/gate/EGIA inspection identities, matching `(run, graph revision, projection revision, stream, gate, generation, frame ID, JPEG SHA-256, byte length)`, and the IsOS owner verifier result. The one-shot duplicate replay must show only `generation_stale`, exactly one added rejection, no added acceptance or change in accepted identity, stage, prompt, mission, or model state, and absence of its private test socket after use and Stop. Include the clean-home failure, restart, safe-stop, legacy graph, and unsupported-future-version paths. A frozen fixture checker or isolated EGIA stub is not this receipt. An unresolved Q01 or Q02 leaves Q03 unclosed.

## Gates and failure evidence

Run `uv run ruff format --check .`, `uv run ruff check .`, `uv run pyright`, `PYTHONPATH=src:libexec uv run lint-imports`, `uv run pytest -q` sequentially, focused stage/Vision/link/restart and event/recovery tests, both frozen fixture checkers, `./bin/islandctl validate`, and `git diff --check` after `uv sync --extra dev --extra vec`. Record tool versions, complete stdout/stderr, exit codes, and any failed first attempt. Keep fixed-port `127.0.0.1:16060` free of another selected EGIA process before the full suite. A tracked CI job must run the source gates and installed-wheel gate on the selected revision; preserve its job URL and artifacts.

Build the `egia==0.1.0` wheel from that commit, install it into a fresh isolated Python 3.12 environment inside a private prefix with a clean IsOS home, and prove Python imports `egia` and `island` from that prefix rather than the checkout. Configure CMake with `-DCMAKE_INSTALL_PREFIX=<prefix> -DISLAND_INSTALL_ETCDIR=<prefix>/etc/island` before `cmake --install`; its default `/etc/island` is outside the test prefix. Public `egia`, `egia-config`, and `islandctl` wrappers are CMake-owned, not wheel console scripts. Invoke the installed wrappers from the prefix, with no source checkout in CWD or inherited `PYTHONPATH`, and explicitly set `EGIA_PYTHON`, `ISLAND_PREFIX`, `ISLAND_MODE=system`, `ISLAND_ETC`, `ISLAND_SHARE`, `ISLAND_CONFIG`, and `EGIA_ETC` to selected installed paths. Verify the resolved config, every selected shared-resource root, installed wrapper, and both imported module paths are inside the prefix; fail on any source checkout, host `/etc/island`, or unexpected path. From the installed prefix run setup identity/catalog/validate/render, both capability probes, and `islandctl validate`; compare exact type/feature IDs and the selected `stages.json` digest. Then run the selected IsOS-managed real-process path, verify EOS metadata and owner-only grants/sockets, all seven stage health states, one exact primitive binding, one governed operation with a terminal receipt, and causal run/correlation IDs. Inject a child failure and same-run restart; reconcile the persisted operation ID without a second Submit or replayed motion. Incomplete/mixed EOS discovery, wrong selected revision, unsafe grant, and unresolved terminal outcome must block writes/ready or remain pending/latched. Verify grant revocation, Vision disconnect and Stop clear transient JPEG, no late callback, owner-order Stop, reaped children, and removed private listener. An authorized reset requires stopped EGIA and two fresh complete safe EOS generations. Preserve the IsOS owner verifier and EGIA replay, not merely process exit logs. Public EOS release compatibility needs its own exact published EOS version and real-process replay.

The Q03 CI job materializes a test-only EOS source-layout archive (`share/`, executable `bin/eosd`, and the `adapters/eos-cxx/CMakeLists.txt` source marker) from the exact EOS contract commit `c43e5a32eafd9bf22b2dba2940662dcded60111c` as sibling `Island-eos/share`, after checking its SHA-256. ## Fixed initial benchmark workloads

Use a deterministic runner under `tests/benchmarks/` after design review; commit its README with the exact fixture generator, scheduler, barrier and invocation before measuring. These are local, read-only measurements with no network model or physical actuator. Run one warm-up then five measured runs on an otherwise idle, pinned environment; never assert a throughput target before reporting a baseline. Keep the complete fixed input fixture or generator seed, its SHA-256 and byte length, per-item monotonic timestamps, IDs, counters, raw samples, and output digests. A benchmark must fail if its expected identities or counts disagree.

1. **Stage evidence delivery.** Compose the same seven `@v0.1` types and the two A04 routes in `tests/egia/test_stages.py`, with a stub complete EOS generation and `auto_drain=False`. Use fixed valid `sample.text: "ready"` and `sample.eos_robot_id: "robot-a"`, unique `r-00000` through `r-09999` resource IDs, current observed times, and a documented payload digest and size. Offer 10,000 ordered resource events at 1,000 events/s using a monotonic scheduler, resource-edge `priority: 0` and no `frequency_hz`. In the baseline, leave the observations route idle. In the contended case, set resource `frequency_hz: 30` and, at each same 1 ms offer tick after resource publication, independently publish one `observations` value with `{"items":[]}`, IDs `o-00000` through `o-09999`, at 1,000/s; set its edge `priority: -10` with no `frequency_hz`. These synthetic observations do not claim to be the output of the resource event's perception transformation. At each `t0 + i × 1 ms` deadline, wait until due, never skip a late offer, publish the item(s) in that order, then call `drain_ready(limit=1)` exactly once. After the last offer, continue one drain per 1 ms until, **for each edge**, `delivered + overflow = offered` and no pending item remains, or fail at a 2-second post-offer timeout. Reject stale/error diagnostics rather than counting them as successful delivery. Record actual monotonic ingress and handler timestamps and wall elapsed time; report resource ingress→perception and observations ingress→context latency **separately**, with per-route IDs, offered/accepted/delivered, overflow and gaps. Stop only after the barrier, assert no post-Stop delivery and zero pending/discarded items. The latest-value single-slot edges can coalesce events; do not require all offered items to be delivered. Add a focused accounting, owner-failure and barrier-timeout test for the runner. Never schedule result, safety, admission, or command traffic as A04 evidence.
2. **Vision read-only admission.** Use the stub owner UDS WebSocket path from `tests/egia/test_vision_evidence.py`, one fixed valid JPEG with recorded SHA-256 and byte length, the selected binding/render (`max_width_px: 1280`, `jpeg_quality: 80`, `target_fps: 30`), and an attested stream. Offer 1,000 strictly increasing generations at no more than 30 frames/s. After each 100 valid frames inject one duplicate of the latest generation: expect exactly ten `generation_stale` rejections and no accepted-state advance. Measure received-frame-to-inspection-available latency and accepted frames/s. This repeated benchmark does not use the one-shot Q01 stale-test socket, whose lifecycle is different. Do not publish JPEG bytes in evidence.

For each case report `N offered`, `N accepted`, `N delivered` (Vision may use accepted as its terminal count), elapsed wall seconds, delivered/elapsed or accepted/elapsed throughput, per-run median and nearest-rank p99 monotonic latency in milliseconds, five-run median and range, overflow/gap/rejection counts, and all errors. Label an offered-rate-limited result as such rather than maximum capacity. Record CPU model/core count, RAM, OS/kernel, Python/uv/EGIA versions, exact commits, power/container/CPU-affinity settings, concurrent load, warm-up duration, clock source, wheel-versus-source execution, and fixture digest/length. Keep raw JSON/CSV and complete logs under ignored `logs/test/<run-id>/egia-bench/`; publish a durable reviewer artifact reference because ignored local logs are not in the PR.

## Evidence and closure

Capture each command with `set -o pipefail` and `tee` into separate `logs/test/<run-id>/` files, recording the exit code and preserving failed attempts. Archive environment inventory, `git rev-parse`/status, lock hash, wheel build/install transcript, source and installed gates, Q01 receipt, Q02 audit reference, selected graph and operation IDs, owner events, failure/restart/Stop logs, and benchmark raw output. Correlate package/version → Apply revision → EOS readiness/discovery → EGIA ready → mission/gate/terminal result → Stop by one selected run and correlation ID. Check redaction, rotation and collector loss against the event contract. Update bilingual first-use steps with actual commands and measured results, obtain independent design and implementation review, then rerun affected gates before declaring Q03 complete.
