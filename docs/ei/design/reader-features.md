# Selected EGIA reader preflight

[中文](../../../docs_cn/ei/design/reader-features.md) · [Owner contract](../interfaces/reader-features.md) · [First use](../develop/build-and-run.md)

**Implemented EGIA owner slice.** P05 adds a no-start runtime probe and exact setup reader sets. IsOS decides deployment admission from the saved graph, verified generation and selected files. EGIA owns only its truthful probe replies and the existing setup validation.

`egia-config` is the graph reader. Its schema-1 `identity` should obtain the four exact supported IDs from the same `LEGACY_EGIA_TYPES` registry used by Validate/Render, sort them, and advertise the feature constants for the implemented adapter operations. It must not claim the future `@v0.1` stage catalog merely because it accepts a `0.1.0` envelope. The four old common nodes remain design-only. They do not compose or execute the A01 pipeline.

The selected `egia` launcher is a configuration reader and EOS client, not a graph reader. Handle `--capabilities` before the TUI selection and runtime imports, and do not run `uv sync` or a virtualenv bootstrap on that path. Report `binary`, product version and only `managed-config-v1` plus `eos-gateway-client-v2`. The latter describes the client compiled against existing Gateway and CapabilityService identities; R02 will qualify the EOS server and ready barrier. A listener or PID does not satisfy that barrier.

The checkout wrapper may resolve an interpreter through `EGIA_PYTHON`, `ISLAND_PYTHON` or `.venv/bin/python`. The implemented probe exits before the checkout's automatic dependency bootstrap and dispatches with `python -B` to a stdlib-only module without importing `egia.main` or writing bytecode. The setup wrapper uses the same source-layout test and honors `ISLAND_LIB` in installed layouts, so selected setup and runtime probes import EGIA from the same module root. IsOS must bind the probe to the interpreter and installed code actually used at spawn, and include those inputs in P04 verification. An interpreter or environment selection change after Apply invalidates that generation before any active child is stopped. The launcher path alone is insufficient evidence of the Python implementation selected by the wrapper.

The [fixture](../../../ei/tests/fixtures/reader_features/README.md) freezes positive probe values, sorted exact IDs, legacy scalar fallback, unknown stage/placement failures, runtime-feature negatives and changed-input no-stop behavior. The EGIA implementation compares real `egia-config setup --json` identity and `egia --capabilities` replies from one selected checkout against that fixture. Subprocess tests cover an absent default interpreter without `uv sync`, an explicit selected interpreter, an installed prefix whose module code changes, and invalid probe arguments. IsOS owns its stub-probe and before-stop replay. P05 closes only the version/feature preflight boundary, leaving R02 readiness and A01 composition to their own milestones.
