# P06 EGIA event producer design

[中文](../../../docs_cn/ei/design/events.md) · [Owner interface](../interfaces/events.md) · [Fixture](../../../ei/tests/fixtures/jsonl_events/README.md)

**P06 producer implemented.** The [owner interface](../interfaces/events.md) defines the wire. This page maps it to current EGIA entrypoints and preserves the private replay. P06 changes logging only; it does not instantiate A01 stage nodes or R02 Gateway commands.

## Entry and readiness

`src/egia/main.py::main` resolves the selected config and calls `configure_logging`. Today `src/egia/lib/logger.py` mints a random `run_id`, sends optional human stderr, writes a rotating owner replay, and can send a legacy Island session datagram. The target parses `ISOS_RUN_ID` before configuring a managed event sink. `--managed` requires a valid `r...` ID and rejects absence/malformed input without sending a JSONL record. Standalone rejects an unexpected manager binding and mints `l<uuidhex>` once. This ID is injected into both owner replay and the new shared projection. A bootstrap exception before a safe sink exists stays in private `main.log`; IsOS observes the selected child exit and emits its own failure.

The event projection is a separate handler after the existing sanitizer. It maps explicit lifecycle, mission, safety and EOS result call sites to the closed role policy; it must not rename or pass through arbitrary existing `event` strings. Managed stderr contains only strict JSONL; disable human stderr and legacy session datagrams for that path. The owner replay remains an independently rotating sink under `var/lib/egia/egia.jsonl`; human logs remain under `var/log/egia`. No IsOS socket is a substitute for the selected pipe. If shared output fails, record a bounded private counter and keep stop/reap progressing.

Emit `egia_starting` after config, contract registry, managed run binding and event sink succeed. Emit `egia_ready` once only after a complete EOS discovery generation is published, required model binding is usable, safety gate/monitor are initialized and the northbound listener has bound. `egia_ready` does not mean a mission succeeded. The current launch can run an empty or sandbox fallback; managed EGIA must not emit ready for those paths when a verified EOS route is required. A startup failure after sink creation emits one `egia_start_failed` with a closed reason; failure before sink creation is reported by IsOS supervision. On shutdown, emit `egia_stopping`, stop accepting proposals, settle/checkpoint known outcomes, then emit one `egia_stopped`: `state:stopped` has `level:info`; `state:stop_unconfirmed` has `level:error` so an unconfirmed stop remains a visible failure. Process kill may leave no terminal event.

## Mapping and ordering

The current `MissionQueue` logs `mission_started`, terminal transitions and checkpoint restores; the new event projection emits `egia_mission_started` only after durable running state, `egia_mission_terminal` after a durable terminal checkpoint, and `egia_recovery_required` for an uncertain restored barrier. `SafetyGate` and `EmergencyLatch` map safe refusal/latch transitions without primitive names or arguments. The EOS link emits `egia_operation_submitted` only after a durable EOS operation ID exists; a terminal result requires a matching EOS receipt, while timeout/disconnect/missing receipt becomes `egia_operation_unknown`. A03 extends these owner boundaries with typed stage, proposal and admission correlations under the reviewed v2 policy. A proposal or graph wire alone never emits submitted or terminal. `correlation_id` is the admitted request ID when valid; otherwise null. If a code needs an ID that is unavailable or malformed, emit the safe owner-private diagnostic and do not fabricate a shared event.

Project only exact typed fields and fixed messages from `egia-role-policy.json`. Validate enum values, IDs, positive counts, canonical admitted EGIA node pointers, whole-line length and UTC timestamp before one write. Drop unsafe candidate fields rather than converting arbitrary objects to text. Field-specific safe reasons such as `internal` preserve an actionable category without leaking an exception. Never take `message`, code or field names from model output, configuration, graph data, primitive arguments or provider responses. The private replay's existing recursive sanitizer remains useful, but shared events require this stricter allowlist.

An owner-local 256-key monotonic table suppresses only repeated noncritical diagnostics for up to 60 seconds and reports a bounded count. Startup, ready, state changes, first warning/failure, latch, unknown outcome, terminal and safety-stop failures bypass suppression. The current `_RepeatSuppressor` has a 4,096-entry replay/file policy; do not reuse its output as the shared event stream because its signature and `repeats` fields differ. On table eviction and shutdown, flush safe counts without blocking stop. A shared write failure increments a bounded owner counter; neither that failure nor IsOS collector outage changes EOS actuation state.

## A03 durable recovery and shared policy revision

The closed fixture `tests/fixtures/jsonl_events/egia-role-policy.json` now has schema `egia-jsonl-role-policy-a03-v2` and 24 codes. The new stage, proposal, admission, mission-restored, monitor and local-reset records carry only reviewed scalar fields. EGIA validates every correlation ID and includes it in the safety-refusal suppression key, so the first refusal for each distinct request remains visible. Latch, reset, admission, unknown, terminal and recovery records bypass suppression. IsOS must mirror this exact fixture before ingesting the new codes.

`OperationLedger` atomically reserves an ID before EOS Submit and keeps pending entries after transport uncertainty. Startup queries `GetOperation` with the same ID after complete discovery; a confirmed terminal receipt settles the checkpoint, while a missing or mismatched receipt remains unknown and blocks safety reset. No restart path calls Submit for an old ID. `SafetyState` writes the affected alias and EOS robot identity set before estop egress using an owner-only atomic file and directory fsync. A local stopped-process CLI takes the same exclusive lock as the runtime and writes one-shot reset authorization; the next launch consumes it and checks all aliases twice before durable unlatch.

The A03 process-boundary test keeps a single stub EOS server alive while two EGIA interpreters share one private state root and fixed synthetic run binding. The first reserves the checkpoint and exits before settlement; the second runs the production pending-operation startup loop and settles only after complete discovery and a saved-ID GetOperation. A separate missing-receipt run retains the checkpoint and latch, then refuses one-shot reset. This owner test does not represent selected IsOS supervision: R06 stops the whole deployment on an unexpected EGIA child exit.

The independent A03 review tightened crash boundaries. `safety-history.json` precedes the latch payload; an engaged marker with a missing payload fails closed. `operations-history.json` and each per-ID index precede the operation payload, so a missing checkpoint is detected. Both latch and one-shot authorization bind an episode ID and selected graph revision; an operation reservation also stores EOS robot identity and graph revision, and terminal state cannot be rewritten. The authorization is consumed immediately after taking the runtime lock, so configuration, discovery or mission checkpoint failures cannot leave it armed. Managed default startup does not clear incomplete missions before restoration.
