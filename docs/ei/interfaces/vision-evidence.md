# EGIA gate Vision evidence

The [Q03 owner qualification design](../design/q03-qualification.md) measures this existing read-only ingress with a repeated stub stream. That benchmark does not use or extend the one-shot Q01 stale-test socket; selected Q01 byte and identity comparison remains a separate prerequisite.

[中文](../../../docs_cn/ei/interfaces/vision-evidence.md) · [Stage contract](pipeline.md) · [Managed configuration](isos-config.md)

EGIA owns a read-only typed ingress named `egia.vision.ingress@v0.1.frame` and a sanitized inspection projection for Q01. This is a process-owned input, **not an eighth stage or an authored graph port**. IsOS creates one selected service binding outside the graph from the applied EOS camera gate `preview` to this exact ingress; the applied graph supplies the camera → gate edge, but contains no cross-core image edge. This choice preserves G06's rule that arbitrary `service_bridge` graph edges are not admitted. No `resource`, A04 text sample, model prompt, journal, command, or actuator route receives the JPEG.

## Selected binding and transport

IsOS pins a nonsecret template in the immutable graph-revision snapshot, then generates `egia/vision-binding.json` and a mode-`0600` owner grant file in a private run-scoped directory. The binding is immutable for one deployment run and contains `schema_version: 1`, `deployment_run_id` (the selected IsOS run ID), `graph_revision` (64 lowercase SHA-256 hex of the saved whole-graph bytes), `projection_revision` (64 lowercase SHA-256 hex of the selected EOS projection bytes), `eos_endpoint` (an IsOS-selected owner-local Vision WebSocket endpoint; the fixed owner-only UDS described by EOS, never TCP or a hard-coded port), `source_path`, `gate_path`, `ingress_type: "egia.vision.ingress@v0.1.frame"`, `render` (`max_width_px`, `jpeg_quality`), and the absolute grant-file path. IsOS, not graph authors or EOS frame metadata, chooses endpoint and grant. EGIA validates the selected endpoint and grant file owner/mode, binds the grant to the exact run/revision/source/gate tuple, and connects only after matching EOS readiness. The EOS server must attest those fields through the selected endpoint and owner grant before any binary payload is trusted. Browser Origin or a loopback address alone is insufficient. IsOS rotates the run ID and grant on each deployment run; an EOS child restart in the same run changes `runtime_stream_id` but not the run ID.

For example, a generated binding is:

```json
{"schema_version":1,"deployment_run_id":"r7-cde","graph_revision":"0123456789abcdef0123456789abcdef0123456789abcdef0123456789abcdef","projection_revision":"aaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaa","eos_endpoint":{"transport":"uds","path":"/run/user/1000/isos/v/cf92cf47318cd17e5d636bbff38aeaf8/eos-vision-owner.sock"},"source_path":"eos/hardware/camera/front","gate_path":"eos/interface/gate/front","ingress_type":"egia.vision.ingress@v0.1.frame","render":{"max_width_px":1280,"jpeg_quality":80},"target_fps":30,"grant_file":"/run/user/1000/isos/control-grants/main/r7-cde/egia-vision.grant"}
```

The owner socket and inspection socket live in a separate private endpoint directory `<runtime-root>/v/<key>/`, where `<key>` is the first 16 SHA-256 bytes of UTF-8 `<deployment>`, one NUL byte, and UTF-8 `<deployment_run_id>`, written as 32 lowercase hex characters. The endpoint directory and its `v` parent are same-UID mode `0700`; both sockets are mode `0600`. The grant and `egia/vision-binding.json` stay under `<runtime-root>/control-grants/<deployment>/<run-id>/`. EGIA derives the endpoint directory from that grant path and selected run ID; it rejects any path, owner, mode, symlink ancestor, or adjacent `vision-verifier.json` whose exact run, graph revision, projection revision, source, gate, or grant digest disagrees. The previous same-run-root socket layout remains readable for safe legacy runs. IsOS revokes both adjacent verifier files before child termination and removes sockets and the endpoint directory after reap.

`schema_version` is a required integer, exactly 1. `deployment_run_id` is a required 1–64 byte ASCII IsOS run ID and must equal the managed process run binding. `graph_revision` is a required 64-character lowercase hex digest and must match the selected `stages.json` revision and EOS active revision. `projection_revision` is required, matches the selected EOS Vision catalog and subscription `revision`, and is distinct from `graph_revision`. `eos_endpoint` is a required typed endpoint object; UDS `path` must be absolute and owner controlled, and TCP is invalid for this Q01 binding. `source_path` and `gate_path` are required canonical applied-graph paths and must resolve to exactly one camera → gate edge. `ingress_type` is required and exact. `render` is required and fixed at `max_width_px:1280`, `jpeg_quality:80`; `target_fps` is required and fixed at 30. They are IsOS-generated values, not EGIA or graph defaults. Identical render values permit Q01 JPEG byte comparison. `grant_file` is a required absolute owner-controlled path; grant bytes never enter JSON, logs, prompts, or inspection. Unknown security-critical fields or conflicting identities fail validation. IsOS passes no user QoS for this binding; EOS's camera → gate `frequency_hz` remains authoritative.

## Frame admission and lifecycle

EGIA sends the existing Vision `subscribe` request for the bound gate and `projection_revision` with the bound render parameters. After owner authentication, the `subscribed` response attests the active graph revision, runtime stream ID, gate, source, and current generation. EGIA accepts a binary frame only if its metadata is a single UTF-8 JSON object of 1–4096 bytes, the JPEG is present and at most 8 MiB with valid SOI/EOI and dimensions, `jpeg_sha256` equals the SHA-256 of the **received JPEG bytes**, and every required EOS provenance field in the [EOS Vision contract](https://github.com/Island-Team/Island-eos/blob/refactor%28v2%29/runtime-main/docs/eos/interfaces/vision.md) is well formed. It compares both saved-graph and EOS-projection revisions, source, gate, render, selected endpoint, run grant and attested stream before publication. The immutable delivery identity is `(graph_revision, runtime_stream_id, gate_path, gate_generation)`; `source_frame_id` is EOS-issued and required even without source sequence/time. `gate_generation` must be positive and strictly greater than the last accepted generation for that gate and stream. A missing sequence/time is allowed and shown as absent, never synthesized.

EGIA retains at most one accepted JPEG transiently for local typed processing and one bounded metadata-only latest observation. Q01 needs inspection only; the frame is **not** a `vision_frame` input to the seven-stage A04 pipeline, and cannot update perception, context, decision, prompt history, mission state, or safety admission. On disconnect, EOS stop, grant revocation, run change, graph change, or EOS stream change, EGIA immediately clears the JPEG and marks the latest observation unavailable. It may retain the previous delivery identity as `last_accepted` for diagnostics, explicitly marked stale. A new attested EOS stream resets its generation baseline only after the new subscription handshake and full run/revision/source/gate verification; an unannounced stream change in a binary frame is rejected. Reconnect within one stream uses the last accepted generation as `after_generation` and the attested stream as `after_runtime_stream_id`; duplicate or older frames never advance the observation. On EGIA stop, cancel the subscriber and clear transient bytes before reporting stopped; no late callback may republish.

The owner ingress tracks saturating `accepted_count`, `rejected_count`, and per-reason `rejection_counts` for the current run. These are **EGIA ingress** counters and never stand in for EOS `cap_wait_count`, `replaced_count`, `gap_count`, or synthetic FIFO `overflow_count`. Rejection is atomic: the JPEG is discarded; latest accepted identity, observation version, stage state, prompts, and model calls do not advance. Stable reason codes are `binding_invalid`, `endpoint_mismatch`, `grant_denied`, `run_mismatch`, `revision_mismatch`, `source_mismatch`, `gate_mismatch`, `stream_mismatch`, `generation_stale`, `metadata_invalid`, `metadata_too_large`, `jpeg_invalid`, `jpeg_too_large`, `digest_mismatch`, `render_mismatch`, and `stopped`. A transport loss sets `disconnected`; it is not a rejected frame. No reason contains raw bytes, grant material, or a free-form peer exception.

## Read-only inspection

A separate owner-only UDS WebSocket path `WS /api/aether/egia/vision/evidence` returns one metadata-only snapshot on connect and then bounded state changes. It accepts no action or image upload message. An unauthorized caller receives HTTP 403 `{"ok":false,"error":"inspection_grant_denied"}` before upgrade; no snapshot is sent. A connected but empty or disconnected source returns `state: "missing"` or `"disconnected"`, not a fabricated frame. A valid snapshot example is:

```json
{"type":"vision_evidence","state":"available","deployment_run_id":"r7-cde","graph_revision":"0123456789abcdef0123456789abcdef0123456789abcdef0123456789abcdef","projection_revision":"aaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaa","runtime_stream_id":"8b4e9b70-5481-4d88-9bd6-4f07cb466ae4","source_path":"eos/hardware/camera/front","source_frame_id":"cam-41","gate_path":"eos/interface/gate/front","gate_generation":7,"sequence":null,"timestamp_unix_ms":null,"width_px":1280,"height_px":720,"render":{"max_width_px":1280,"jpeg_quality":80},"jpeg_sha256":"c8f1b57ba3b319e7c5ddce3dac7f09c729d8d4bce2259c4f03d68cdbb7f69f0d","jpeg_length_bytes":12345,"accepted_count":1,"rejected_count":0,"rejection_counts":{}}
```

`jpeg_length_bytes` is a positive integer in received bytes (1 through 8 MiB) for the digest-verified JPEG, and null without a current frame. The digest is a format example for omitted JPEG bytes. `type` and `state` are required enums; `deployment_run_id`, `graph_revision`, `projection_revision`, `source_path`, `gate_path`, `render`, and counters remain present for a selected binding even when no frame exists. `runtime_stream_id`, `source_frame_id`, `gate_generation`, optional source `sequence`/`timestamp_unix_ms`, dimensions, digest and `jpeg_length_bytes` are null while `missing` or `disconnected`; the previous identity may appear only in a separately marked `last_accepted` object. `accepted_count`/`rejected_count` are unsigned saturating 64-bit integers for this run; `rejection_counts` contains only the closed codes above. The entire JSON frame is bounded to 4 KiB. Inspection exposes no JPEG, grant, endpoint path, or model content and does not imply actuation or stage evidence.

An implementation contract test uses a stub EOS WebSocket to cover valid delivery, optional source fields, malformed length/JSON/JPEG, both size bounds, digest mismatch, wrong endpoint/run/revision/source/gate/render/stream, duplicate and older generation, disconnect, EOS restart and new run. It verifies each rejection leaves the observation and all stage/prompt state unchanged; stop admits no late frame. A selected Q01 replay compares the EOS and EGIA delivery identity, validates each rendition digest, and archives metadata and lengths without JPEG bytes.

## Frozen 0.x client and inspection authorization

EGIA requires runtime `--capabilities` tokens `vision-evidence-ingress-v1` and `vision-inspection-uds-v1` before IsOS may enable this binding. `EGIA_EOS_VISION_GRANT_FILE` must equal the generated `grant_file` path and be a same-UID mode-0600 regular file containing exactly 64 lowercase hex digits plus newline; EGIA never accepts a grant in a graph, URI, command line or WebSocket message. It opens only the generated `eos_endpoint` UDS using `ws://localhost/api/eos/v2/vision/owner-ws`, sends `Host: localhost` and `Authorization: Bearer <64-lowercase-hex>` during HTTP upgrade, and sends no `Origin` or `Sec-Fetch-*`. HTTP 403 `owner_grant_denied`, 409 `owner_binding_stale`, 503 `vision_unavailable`, timeout or a wrong socket peer fail before subscription and publish no observation. The first masked text message within five seconds is `{"op":"subscribe","gate_path":"eos/interface/gate/front","revision":"aaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaa","target_fps":30,"max_width_px":1280,"jpeg_quality":80}`; on same-stream reconnect it additionally carries both `after_generation` and `after_runtime_stream_id`. EGIA requires the `subscribed` attestation before any binary frame, accepts generation `0` with no JPEG as an empty ready handshake, and verifies both revisions, source/gate and stream against its binding and the selected endpoint. A text error followed by WebSocket 1008 or EOS 1012 clears current evidence. It does not use direct gRPC `CaptureFrames` or A04 `resource` as a fallback.

Inspection is a **different** listener and grant. IsOS sets `EGIA_VISION_INSPECTION_SOCKET=<endpoint-dir>/egia-vision-inspection.sock` and `EGIA_VISION_INSPECTION_VERIFIER_FILE=<endpoint-dir>/egia-vision-inspection-verifier.json` for the managed EGIA child. EGIA checks the mode-0700 same-UID parent, binds the UDS at mode 0600, and reads a mode-0600 verifier with exact `schema_version:1`, `run_id`, `graph_revision` and `inspection_sha256` of a separate 32-byte `vision-inspection` grant. Only `GET /api/aether/egia/vision/evidence` with `Host: localhost`, no `Origin`/`Sec-Fetch-*`, same-UID `SO_PEERCRED`, and `Authorization: Bearer <64-lowercase-hex>` may upgrade. The bearer digest is compared in constant time. Bad bearer returns HTTP 403 `{"ok":false,"error":"inspection_grant_denied"}`; stale run returns 409 `inspection_run_stale`; unavailable owner state returns 503 `inspection_unavailable`. After HTTP 101, the read-only stream emits one bounded snapshot and later state changes; client text or binary messages are invalid and close 1008. IsOS keeps the inspection grant in its private run root and supplies its path only to the owner-local Q01 verifier; the public EGIA TCP northbound listener, IsosUI and process-status never receive it. Stop closes this listener and clears the latest current frame before reporting stopped. The subscriber grant cannot authenticate inspection, and the inspection grant cannot subscribe to EOS.

The frozen [EGIA Q01 cases](../../../ei/tests/fixtures/q01_vision_evidence/README.md) require accepted identity and explicit run/revision/source/gate/stream, bound, digest, duplicate, disconnect and stop negatives with no stage or prompt advance. They are implementation inputs, not live receipt evidence.

## Implemented EGIA reader (Q01 owner slice)

The managed `bin/egia --capabilities` probe advertises `vision-evidence-ingress-v1` and `vision-inspection-uds-v1`. When IsOS sets the four `EGIA_*VISION*` file/socket variables, startup reads the selected `egia/vision-binding.json` as a same-UID mode-0600 file under a mode-0700 run directory; the short endpoint directory is independently checked, checks its run ID and `stages.json` graph revision, and reads the separate mode-0600 EOS grant. The private client uses the selected UDS and bearer for the EOS owner subscription. It verifies the attested stream and all frame identities, dimensions, byte digest, size limits and strictly increasing generation before publishing a metadata-only inspection snapshot. The snapshot includes `jpeg_length_bytes` for the verified received JPEG. Disconnect and Stop clear the transient JPEG; the prior identity is labeled stale. No frame is sent to stages, prompts, model input or actuator routes.

IsOS also supplies `EGIA_VISION_INSPECTION_SOCKET` and `EGIA_VISION_INSPECTION_VERIFIER_FILE`. EGIA binds a mode-0600 owner UDS, checks same-UID peer credentials and the separate inspection grant digest before upgrade, and closes on client messages. The selected owner verifier can inspect one current snapshot and bounded changes using `WS /api/aether/egia/vision/evidence`; the public northbound TCP listener does not expose this route. The inspection socket and transient bytes are removed before EGIA reports a clean stop.

The focused implementation gate uses `uv run pytest -q tests/egia/test_vision_evidence.py`; the stub test covers the owner handshake, an accepted rendition, read-only inspection and grant separation. The full repository gate results are recorded in the paired development guide. A selected IsOS/EOS/EGIA process replay and cross-owner byte comparison remain Q01 qualification work.

The frozen `tests/fixtures/q01_vision_evidence/cases.json` retains `status: "target_not_implemented"` as its 2026-11-02 design-snapshot marker. Its checker validates case structure only. Current behavior is checked by `tests/egia/test_vision_evidence.py`; neither artifact substitutes for the selected Q01 process replay.

## Private Q01 duplicate-generation test seam

Only a selected managed Vision child with the exact inherited manager environment value `EGIA_Q01_STALE_TEST=1` creates this test seam. EGIA captures this value before loading any local `.env`, so a dotenv value cannot enable it. The flag is absent from graph, generated configuration, capability probes, process status, and inspection. After validating the selected run binding, EOS owner grant, and inspection verifier, EGIA derives `egia-vision-stale-test.sock` beside the inspection socket. The absolute socket path has an absent pre-bind entry, a non-symlink same-UID mode-0700 parent, and a same-UID mode-0600 socket. A preexisting file or symlink blocks startup without being removed. Each peer must have EGIA's effective UID by `SO_PEERCRED`. No TCP or public route exists. Without the exact opt-in, EGIA creates no test socket and retains no duplicate-test metadata.

The socket accepts one newline-terminated UTF-8 JSON object of at most 1024 bytes, with a two-second read timeout and exactly these keys: `schema_version` (integer 1), `op` (`replay_latest`), `deployment_run_id` (selected run ID), `graph_revision` (64 lowercase SHA-256 hex characters), `runtime_stream_id` (current attested stream ID), `gate_generation` (positive integer), `source_frame_id` (current EOS frame ID), and `jpeg_sha256` (64 lowercase SHA-256 hex characters). These values only compare against current accepted state. The caller supplies no JPEG, metadata replacement, endpoint, grant, graph edge, or command. Extra fields, malformed JSON and oversized requests return `invalid_request`; wrong run or graph revision returns `binding_stale`; a changed current stream, generation, frame ID or digest returns `target_changed`. A disconnected or revoked source returns `unavailable`; a stopped owner returns `stopped`. Only the matching current request is consumed.

EGIA retains a copy of the full validated metadata object only in this test mode, alongside the existing single transient JPEG. Under one admission lock it rechecks the owner grant and exact target, captures a metadata-only `before` snapshot, reconstructs the original wire frame from that metadata and JPEG, invokes the ordinary `VisionEvidence.accept` validation body, and captures `after` before a normal EOS frame can interleave. A successful test response is one JSON line with `schema_version:1`, `op:"replay_latest"`, `injected:true`, `reason_code:"generation_stale"`, and sanitized `before`/`after` inspection snapshots. `accepted_count` and the current frame identity, digest and byte length stay equal; `rejected_count` and `rejection_counts.generation_stale` each increase by one. Other responses use `injected:false` and a closed reason code, without snapshots. The socket closes and unlinks after one actual duplicate even if the response write fails. If startup fails after bind, EGIA closes the listener. Once the created pathname inode is recorded, cleanup removes only that inode and preserves any replacement. If the first pathname stat fails before ownership is recorded, EGIA leaves the entry untouched: its own socket is non-serving and confined to the private endpoint directory until endpoint-directory cleanup, while a replacement Unix socket remains owned by its creator. Disconnect, stream change, grant loss and Stop clear replay metadata; grant loss and Stop close the socket. Production inspection remains read-only and independent.
