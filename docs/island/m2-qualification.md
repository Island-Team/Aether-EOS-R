## First-use replay order

1. Start `isos serve` in the isolated home. Before any admitted run, read `process-status` and the P07 `view=current` page. Expect a manager-session scope with a pending `first_prelaunch_failure` anchor. Trigger one bad package link or Apply and prove the first typed package/Apply failure is pinned outside filtered `lines`; a Validate-only failure must not become this anchor.
2. Link or install the valid exact package. Preview `sim-hardware` for `pick-place` and `navigation`. POST each draft to `/api/isos/v1/node-options`; choose available stable scene, camera, base and manipulator IDs with matching `simulator_node` bindings. Requery after the scene changes. Assert unavailable saved IDs remain visible but fail Apply, and a malformed path-like ID fails at its exact setting pointer. No preview or option read changes saved bytes.
3. Validate and revision-check Apply the `0.1.0` graph. Verify the receipt again, selected scene XML/profile/digests and library, generated schema-2 snapshot, private permissions, exact selected EOS and optional EGIA binaries, and saved revision. Repeat Apply for the same revision to prove idempotence. Read the selected setup/runtime identities and required feature sets through P05. A missing graph or runtime feature returns `reader_feature_unsupported` at `/version` or the requiring process `/node_type`; a registered exact type absent from the selected reader set returns `reader_type_unsupported` at that node's `/node_type`. An unregistered type returns G01 `unsupported_node_type` before P05, while an altered sidecar returns P01 `package_invalid_sidecar` at `/package`, and an uninstalled public pin returns P01 `package_missing_file` at the process `/package` before reader preflight. IsOS separately tests the unreachable public catalog mismatch in its isolated `contributed_type_needs_exact_catalog_pin` predicate: an injected 0.1.0 catalog contribution against a 0.1.1 graph returns `reader_package_pin_mismatch` at `/package`. Each failure precedes child spawn or active stop. A changed selected binary, default or interpreter/module inventory requires explicit new Apply.
4. Run the EOS-only graph. Compare `process-status` saved and active revisions, run ID, child PIDs, and owner-ready events. The deployment `view=current` scope begins when the run is admitted and retains an unfiltered first ready or failure anchor before detail filters. A PID, bound socket, startup line or log row alone is not readiness. The EGIA-enabled graph is a separate negative case: exact selected setup and runtime identities advertise the reader features, while public Validate and Apply return `generated_owner_rejected` at `/cores/egia` because the complete EOS gRPC Gateway endpoint is absent before R02. No EGIA Run or ready claim is made.
5. Read P07 pages with source, node and correlation filters after the anchor. Force normal log rotation with bounded events; continue a retained cursor with no gap. Expire a cursor beyond retention and expect `log_cursor_expired` with a same-run rebase. Admit a new run after a valid Restart and expect `log_run_changed`, new scope and new anchor. Stop, failed status, PID loss and manager restart retain the last admitted run identity. An empty filtered page with advancing cursor and no diagnostic means no match. Inject collector outage and recovery, and assert `log_collector_gap` or `log_anchor_unavailable` with known count or null; never invent a zero-loss claim. If run identity is unprovable, expect HTTP 503 `log_scope_unavailable`, not a manager fallback.
6. On disposable linked content, change an asset or executable byte and test a new Apply, Run and live Restart. Expect P01/P02 typed rejection before saved-byte publication or child stop/replacement; compare prior PIDs and active revision. Repeat with a future graph version, unavailable scene/device, separate feature and exact-type reader mismatches, unregistered or unverified contributions, wrong exact pin and generated snapshot tamper. For a failed restart, inspect the manager-session failure correlation without relabeling the retained deployment run. Restore verified inputs by an explicit relink or Apply, then stop and confirm owner status and terminal event; M3 later adds the actuator-stop-before-simulator-reap proof.

M2-21 uses two evidence layers. In the public replay, replacing `cursor-state.json` with a directory after Apply makes Run return HTTP 500 `log_scope_publish_failed` at `/run_id` with no child. This blocks state loading before publication; it does not inject a parent-directory fsync failure. IsOS owner unit tests separately cover a pre-save failure and simulated post-rename uncertainty, proving that a surviving new run retains its identity and reports an unavailable anchor. An actual failed parent fsync syscall is outside this replay evidence.

The [machine cases](../../tests/fixtures/m2_qualification/README.md) name each positive and negative boundary. The runner must save full command output, JSON responses and status snapshots in its ignored run directory, redact copied human-facing summaries, and compare saved **bytes** as well as revision digests. A failure to collect an expected first event is a failed M2 gate, even when the functional operation succeeded.
