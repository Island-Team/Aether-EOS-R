# Q01 integrated first-use qualification design

[中文](../../docs_cn/island/q01-first-use-design_cn.md) · [0.x TODO](implementation-todo.md) · [Milestone cycle](implementation-milestones.md) · [Scoped Restart proof](q01-restart.md)

**Design status:** independently reviewed and qualified for Q01 on the selected five owner commits below. This page defines the qualification flow and evidence predicates across existing owner interfaces; it adds no public wire field or command authority.

## Owner flow and fixed inputs

IsOS owns the exact saved graph bytes, revision, verified package receipt, selected node options, generated configuration, Apply, run identity, grants, log scope, Restart and Stop. EOS reads the applied graph, owns active revision, live health, Dispatcher admission, journal and direct MuJoCo child. EGIA owns mission state, proposal, safety decision, operation checkpoint and result. IsosUI renders owner state and sends one authorized `primitive_typed` request for its active binding. A graph edge declares a binding and never executes a browser command. The existing [EOS gRPC](../eos/interfaces/grpc.md), [simulator Stop](../eos/interfaces/simulator-stop.md) and [browser bridge](../eos/interfaces/external/http.md) contracts govern the EOS boundaries; IsOS `docs/isos/interfaces/{package-verification,mujoco-catalog,node-options,local-api,log-cursors,dependent-stop,control-grants}.md` and EGIA `docs/egia/interfaces/{pipeline,safety-reset}.md` govern their respective boundaries.

Before launch, record exact merged source commits for EOS, IsOS, EGIA, IsosUI and MuJoCo; SHA-256 of the selected binaries, UI dist files, MuJoCo archive/release/sidecar, fixtures and replay source; relevant build environment; and reproducible commands. The first implementation candidate starts from EOS `bb3d64536d540967064e0de7048b5d2517082dd6` and the already reviewed [scoped Restart proof](q01-restart.md). All owner pins must be rechecked against remote integration heads before the live run. Build selected code into stable paths, require clean owner source checkouts, and record the actual binary hashes. Historical evidence with earlier pins is separately labeled and cannot replace a current-pin live assertion.

The main operator flow uses one fresh private `ISOS_HOME` and one IsOS manager session through final Stop. Legacy, future-version and unsafe-process cases use separate disposable subhomes so they cannot alter the main applied graph or its run history. The qualification script must never modify the saved graph behind IsOS, clear EOS or EGIA safety latches, inject a grant into logs, or infer readiness from a startup log line.

## Main first-use sequence

| Step | Owner action and required observation |
| --- | --- |
| 1. Install | Initialize empty home; capture raw graph bytes/revision, active revision and child set. Run `isos pkg install --manifest <release.json> --asset <archive> --allow-unapproved`. Require schema-2 receipt with exact `island/mujoco-sim@0.1.1`, `source_kind:local_candidate`, source commit, archive/release/sidecar SHA-256 and canonical installed payload digest. Installation alone changes no graph bytes, active revision, run ID or children. Archive receipt and installed payload for offline checks. |
| 2. Select | `POST /node-sets/preview` composes the MuJoCo set into a draft without saving. `POST /node-options` inspects that draft with `graph_revision:null`; selected scene, camera, base, manipulator and simulator device IDs must be available under the exact pin, while at least one unavailable option stays visibly unavailable. The socket is an owner-only Unix path, not an option ID; check its path and ownership through preview, Apply and Run. Add the seven EGIA stages, package-contributed process type, generic EOS devices, fixed safety routes and two eligible routed evidence edges. Preserve preview bytes, option rows, selected IDs and catalog metadata. |
| 3. Fail then Apply | Before any launch, read unfiltered manager-session `GET /logs?view=current&source=all` and retain its pending scope. Validate an invalid edge draft, then issue an actual revision-checked invalid `PUT /node-graph`; require HTTP 422, exact diagnostic code/path, no saved/active/child change and first `deployment_preflight_failed` anchor with that diagnostic. Correct the draft, Validate, and revision-checked Apply. Require returned revision = SHA-256 of raw saved bytes, active revision null, selected package and generated configuration/EGIA overlay bound to the same revision. Re-read `GET /node-options` and require `graph_revision` equal to saved bytes. |
| 4. Launch and control | Launch through IsOS. Require EOS, MuJoCo, bridge, config and EGIA owner readiness, one run ID, matching saved/active/overlay revision, and complete EOS gRPC discovery. Drive one supervised EGIA mission through stage → proposal → admission → submit → terminal with one operation ID. Inspect the selected IsosUI node card and make one real visible UI click on one active primitive binding; preserve DOM/binding/result and distinct browser command ID. Each ID must map to exactly one typed, admitted, terminal EOS journal record with correct run, revision, ingress, role, target and arguments. Neither a graph wire nor local UI state proves execution. |
| 4a. Camera evidence | At the exact selected pins, run a bounded camera case in the main deployment or a separate disposable selected deployment: one MuJoCo camera frame with source node, source sequence, capture generation, frame ID and saved graph revision must pass the EOS camera route and gate, appear in Vision's read-only observation and reach EGIA's read-only evidence input with the same provenance. Inject one stale generation and one wrong revision and require explicit rejection without updating either consumer. Apply a positive `frequency_hz` cap to an eligible image route, drive controlled overproduction, and require route-status `cap_wait_count` plus a visible `replaced_count`/`gap_count` increase while delivered generations remain ordered and bounded. Image routes retain the latest frame; their loss is replacement, not FIFO `overflow_count`. A separate selected-pin synthetic state/event FIFO case must overflow its 64-record/1-MiB bound and expose `overflow_count`/`gap_count`, with no actuator route affected. Archive raw metadata-only camera/gate/Vision/EGIA observations and route counters, excluding image bytes, then verify source/revision/generation and rejection/counter order offline. If an owner lacks a read-only observation seam, implement and review that owner slice before Q01 closure. |
| 5. Logs | Capture the unfiltered first ready/failure anchor before filtering. Use a separate correlation-filtered cursor for each mission and browser ID; paginate bounded pages to the matching owner result. Reusing an unfiltered cursor with changed filters must return `log_cursor_filter_mismatch`. Preserve raw JSONL, response pages, opaque cursors, scope IDs and rotation evidence. Status, rather than logs, remains authoritative live state. |
| 6. Failure and Restart | Inject the bounded HTTP-200 invalid-controller reply of the [scoped Restart proof](q01-restart.md); require owner parse attempts through the configured limit, failed mission and no new EOS Submit or movement. Clear only the model fault. Explicit IsOS Restart in the same manager must confirm old Stop before replacement, reap old PIDs, rotate run/grants, preserve saved revision, and establish new active revision and complete EOS plus planner-visible EGIA discovery. An old operation is opaque under the new grant (`NOT_FOUND`), the retired grant is unauthorized, and no old movement is replayed. A fresh mission has a fresh ID and one correlated EOS result. The old unfiltered log cursor returns `log_run_changed`; the new run gets its own anchor. |
| 7. Stop | Issue governed robot Stop and IsOS Stop. Require a confirmed owner terminal, EOS selected Stop receipt predicates, simulator termination after actuator quiescence, child reap and socket cleanup. A forced, lost-receipt or unknown Stop is a negative case and cannot satisfy this row. |

## Archive and review gate

The retained `logs/test/<run-id>/` archive has raw commands/stdout/stderr, environment and exact source/binary hashes, original asset archive and installed payload/receipt/sidecar, raw saved graph/generated overlay, selected catalog/options, UI served assets and DOM/result, IsOS event JSONL and cursor pages, EGIA owner events/checkpoints, EOS `.rec` records and journal SHA manifest, process status/reap observations, and migration source/preview/saved bytes. Grant contents and model prompts are excluded. A checksum manifest covers every immutable file without self-reference. The offline verifier reads only the archive: it checks exact file coverage and hashes, owner identities and ordering, saved/active/overlay revisions, command/result/journal correlation, first anchors and cursor scopes, Stop/reap proof and migration diagnostics. It never reads a transient home, live `/proc`, source checkout or network. Tamper copies must fail for at least package/archive bytes, graph/revision, UI asset, journal record, log scope/cursor, and migration bytes.

The R06/A03 package comparison retains nonempty selected asset `required_libraries` and `tested_ubuntu` through the installed view. Only contract-defined empty omissions are normalized before full equality: installed `data_types: []` when the selected release omits it, or selected empty asset arrays when the installed view omits them. Receipt SHA and evidence manifest are separate byte-integrity checks; resealed mutations of nonempty libraries, Ubuntu support, or data types must fail the semantic comparison.

Before implementation, obtain independent design review of this owner-flow matrix and frozen fixtures. For the implementation branch, add meaningful focused and cross-owner negative tests, then run EOS formatting, strict Clippy, serial workspace tests and build; IsOS Cargo gates; EGIA Ruff, pytest, pyright and import checks; IsosUI tests and both builds; and MuJoCo CMake/CTest where affected. Save complete commands/results under the same run ID, obtain independent implementation review, and leave Q01 unchecked until the complete selected-pin replay and prior-evidence bindings pass. Q02 last-caller cleanup and Q03/Q04 release evidence remain later gates.
