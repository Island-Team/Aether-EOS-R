# Q03 cross-repository qualification design

[中文](../../docs_cn/island/q03-qualification_cn.md) · [Milestones](implementation-milestones.md) · [Detailed TODO](implementation-todo.md) · [Q01 first use](q01-first-use-design.md) · [Q02 last callers](../eos/maintenance/q02-evidence.md)

Q03 qualifies the selected 0.x owner heads after Q01 and Q02. It does not create a new graph, actuator, browser, model, or package contract. IsOS owns applied graph/package authority and process supervision; EOS owns live admission, journal, child and health; MuJoCo owns its private simulator socket; EGIA owns agent state; IsosUI presents owner-reported state. Every owner runs its source gates and an installed boundary. The cross-owner gate replays the Q01 clean-home operator path with EOS after Q02. An old Q01 archive is reference evidence, not proof that a later EOS commit was installed and exercised.

## Frozen inputs and acceptance

At planning time, remote heads are EOS `refactor(v2)/runtime-main` `dea83f514024dcd577e0284e06d00e5e753ff5a8`, IsOS `master` `00c1d7aa184de8b969e6e40472bf9b1fa55032ff`, EGIA `master` `d3868d2763c35d9f6bfed80d75edb7a1844ef54e`, IsosUI `master` `920995788d8e29dd6ab594d31278033bb791cfeb`, and MuJoCo `master` `4e6b5449ccd25be53ad95b13baa2c89f7ed91e10`. These are starting pins, not release pins. Recheck remotes before every owner PR and selected replay. Record source and built binary/asset hashes, MuJoCo receipt, selected graph bytes/revision, active revision, run IDs and command/result IDs. A build from a stale primary checkout cannot substitute for its selected remote head. Preserve untracked `temp_design.md` in the EOS and IsOS primary checkouts.

The selected Q01 archive in the EOS primary checkout, `logs/test/20261103-q01-full-current/live-3/`, and its externally pinned verifier establish the prior clean-home six-case matrix, each case with positive and negative assertions. Its wrapper exited 143 after the scoped pass and final Stop; Q03 must preserve that process-exit distinction. Q03 runs a fresh installed route after Q02 with install → select → Validate/Apply → launch/readiness → inspect/control → causal current-run logs → injected failure/Restart → safe Stop → explicit migration, including unsupported graph/package/edge and unknown-outcome paths. The new selected-pin archive must pass `tests/verify_q01.py` with five externally supplied source commits. Its predicates include saved/active/generated-overlay revision agreement in one run; readiness confirmed by owner state before logs; one browser command ID linked to an admitted terminal EOS journal record and current-run log; no old grant or operation replay after Restart; and confirmed Stop before simulator termination and reap. Record browser UI evidence against the actually served selected `dist/local`, including one active primitive binding and selected Vision generation/digest; serve `dist/hosted` separately under `/isosui/` and test both editor URLs. Stop and reap must precede cleanup. A screenshot, process exit or old archive alone does not pass this gate.

Each owner records its exact fixture bytes, counts, rates and timeout before running. A benchmark runner is a qualification tool, not a production runtime path; it must have focused tests for sample accounting, failure and timeout. EOS's existing example must be extended or accompanied by a reviewed runner that retains per-call monotonic samples, checks each Result outcome, emits success/reject/error counts and wall duration, and uses a declared median method with nearest-rank p99; its current printed aggregates alone do not satisfy Q03. No throughput or latency target is asserted without a measured baseline. For each workload report successful operations, errors/rejections/gaps, wall duration, throughput, median and nearest-rank p99 from monotonic per-operation samples, plus all raw samples. Repeat at least three times (five for EOS/EGIA if cheap) and report each repetition and aggregation. Record CPU model/core count, memory, OS/kernel, compiler/runtime versions, MuJoCo/Node/browser versions where used, build mode, exact source and input hashes, concurrency and display/GPU state. Do not equate an offered-rate cap with maximum capacity or mix socket, HTTP and browser latency in one number.

## Evidence and workflow

Owner branches are focused `refactor(v2)/<topic>` worktrees from fresh remote integration heads; EOS targets `refactor(v2)/runtime-main`, siblings target `master`. Before implementation, each owner records the contract, fixture/workload design and bilingual first-use steps, then obtains independent design review. An independent agent reviews the implementation, negative paths, installed evidence and performance calculations before its PR. Save complete command output and raw benchmark files under ignored `logs/test/<run-id>/`; tracked English/Chinese evidence pages give exact commands, environment, result counts, initial failures and rerun dispositions. Copy ignored logs with a checksum manifest to a durable reviewer-accessible location before removing any worktree. Q03 qualifies reviewed topic heads and one selected cross-owner installed replay. Q04 reviews and squash merges the scoped PRs, verifies remote targets, replays affected boundaries on merged heads, removes only completed topic branches/worktrees, updates release notes, and then considers EOS integration-to-master and selected tags. A first integration merge cannot be used retroactively as Q03 topic-head evidence.
