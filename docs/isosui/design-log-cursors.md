# Log cursor panel design — P07

[中文](../../docs_cn/isosui/design-log-cursors_cn.md) · [UI contract](interfaces/log-cursors.md) · [Workbench design](design.md)

The existing `IsosLogsPanel` uses a single mutable cursor, polls `/logs` every 1.2 seconds and clears rows on `rotated`. Its `LogLine` type only carries timestamp, level, source and message. P07 extends the service adapter in `src/services/isos/node-graph.ts` and a pure panel state reducer; React components never assemble log URLs. IsOS P07 supplies first-event and run-bound cursor semantics. Browser console lines remain in a separate section, rather than being sorted into the authoritative server stream by timestamp.

## State machine

Represent selection as IsOS `scope:{kind:manager_session|deployment_run,run_id,active_revision}` from the opt-in current-log response, with `selection_generation`. The state also holds `{anchor,anchor_state,query,lines,cursor,gap,follow,connection}`. A stopped or failed deployment, lost PID, cleared active revision or manager restart keeps IsOS-persisted `last_run_id` scope; only an admitted new run changes it. P07 has no clear endpoint. An initial or changed scope starts a new generation, cancels the old request, clears its detail rows and cursor, then requests a `view=current` page whose anchor is unfiltered. The anchor is displayed above filters. While the anchor is pending, `event=null` and detail `lines=[]`; keep the same bound cursor and display waiting. Once found, the same response carries detail lines strictly after the anchor; source/level/node/correlation filters apply to those lines only. Changing a filter resets only that query's cursor and detail rows; it cannot hide or overwrite the anchor. Every async result carries its generation and exact selection, so a late response for an older run is ignored. Status is fetched before a first page and rechecked after reconnect or scope change, but never selects the log scope from PID or active revision.

Process status also reports `run_id_state:none|known|unavailable`. Only `none`, backed by IsOS's durable never-run marker, allows manager scope. If status says unavailable or `view=current` returns HTTP 503 `log_scope_unavailable` at `/scope`, retain prior rows as stale, stop claiming a current run and show the owner error; retry after owner recovery without guessing a manager session. A filter HTTP 400 `log_node_path_invalid` or `log_correlation_id_invalid` is attached to the respective input path. A cursor 400 at `/query/cursor` resets only the rejected query after explaining it. Alerts never echo an opaque token or filter value.

Use IsOS's accepted sequence/cursor order for display. Do not sort server rows by `timestamp` or combine browser rows into the run. Deduplicate by IsOS event identity when provided; otherwise rely on the opaque cursor and response boundary, never a timestamp/message key. Rows remain capped at 1,000. One request is in flight; visible Follow polls at a bounded interval, hidden or paused panels do not poll. A failed request preserves cursor and rows and backs off to 30 seconds. On recovery, status is checked first. A `log_cursor_expired` or `log_collector_gap` response follows the server's same-run resume token and shows a persistent gap banner until the operator acknowledges it; `log_run_changed` starts a new scope and boundary instead. No blind reset to an unscoped first page. The `rotated` flag alone never causes silent row deletion.

The panel distinguishes five nonrow states: no qualifying anchor yet (`pending`), no matching filtered detail event (normal empty page with advancing cursor and no diagnostic), anchor unavailable (`log_anchor_unavailable`), collector unavailable, and a retention gap. Anchor unavailable and retention gap display a loss alert; collector unavailable displays a connection alert. A new run boundary names both old and new safe IDs, clears old detail rows, and does not offer a historical-run selector in P07. A manager-session package/Apply failure while a prior run exists remains a manager event visible through the legacy source view and status; it does not reassign the P07 current-run scope. The Home status badge and process readiness are rendered from IsOS status, never from `eos_ready`, `deployment_ready` or a PID in a log row. A first failure and a first ready event use the same anchored navigation, with a clear outcome label.

On process-control HTTP 500 `log_scope_publish_failed` at `/run_id`, show the typed failure before any child claim. A failed or uncertain durability boundary can leave either the prior scope or a surviving new run; invalidate the local request generation and re-read status plus `view=current` rather than assuming one outcome. If the new scope survived without a child, IsOS may return an unavailable anchor; show its loss diagnostic and no fabricated readiness.

The UI renders event fields as escaped text, displays source/core/run/correlation and the saved-graph pointer without treating it as a filesystem link, and copies only safe IDs. `role=log` has `aria-live=off` for rows; a separate `role=alert` reports collector errors and gaps, while `aria-live=polite` announces a new run or anchor once. Both language copies distinguish status, gap and filter-empty states. Keyboard focus remains on the filter or Jump to first control after a refresh. Source/node/correlation inputs are bounded to the IsOS contract, and invalid input never triggers a request.

The [fixtures](../../ui/tests/fixtures/log_cursors/README.md) freeze the reducer and service boundaries: manager failure, launch switch, first ready/failure before filters, old-run response race, rotation with and without loss, stale cursor, collector outage/recovery, new run, and legacy API fallback. Implementation tests should use a stub IsOS HTTP service and fake timers, then build both local and hosted bundles. Full output belongs under ignored `logs/test/<run-id>/`.

JSON syntax, Python compilation and `git diff --check` pass. `npm test` passes 62 tests in 17 files; `npm run build` passes type checking and both local/hosted bundles and manifests. These run against unchanged UI source, so they qualify the design artifacts and existing baseline, not P07 behavior. Complete commands and output are in ignored `logs/test/20261101-p07-log-cursors-design-final/`.

Implementation evidence (2026-11-01): the service requests `view=current` with the exact detail query and validates the owner response before entering current-run mode. The panel pins the unfiltered first event, preserves accepted row order and retained rows across rotation, reports bounded per-code gaps, resets a rejected cursor, distinguishes a new run, backs off collector failures for 30 seconds, and separates browser diagnostics. A typed Run publication failure aborts and invalidates the prior in-flight read, marks old rows stale, then immediately rechecks status and current logs. Repeated acknowledged gap counts stay dismissed within that run; new loss counts alert again. Run identity unavailable has its own bilingual text, separate from anchor loss. The pending-to-found anchor transition has one polite announcement. Stub HTTP and mounted fake-timer tests cover those races and states alongside manager failure, first ready/failure, rotation, cursor rejection, 503, collector recovery and legacy fallback. With Node 22.23.2 and npm 10.9.9, clean `npm ci` passes, `npm test` passes 83 tests in 20 files, `npm run typecheck` passes, and `npm run build` validates both local and hosted bundles/manifests.
