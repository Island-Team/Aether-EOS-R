# Vision provenance display — Q01 implementation

[中文](../../../docs_cn/isosui/interfaces/vision-provenance_cn.md) · [Workspace panels](workspace-panels.md)

IsosUI owns the browser display of EOS Vision frames. It reads IsOS's current `process-status` run ID, saved and active graph revisions, and the nonsecret `vision_evidence` projection before opening the EOS Vision WebSocket. EOS owns frame metadata and JPEG bytes; IsOS owns the selected gate/source/render binding; EGIA owns its separate typed inspection. The UI never treats a displayed image as an actuator outcome.

For Q01, `process-status.vision_evidence` must contain a selected `gate_path`, `source_path`, `projection_revision` and `{max_width_px,jpeg_quality}` for the current known run and equal saved/active revision. The UI sends that `projection_revision` as the existing subscription `revision` and those exact render parameters. The IsOS active revision remains the saved whole-graph digest, distinct from the EOS projection digest. EOS's additive `subscribed` response must attest `graph_revision`, `projection_revision`, `runtime_stream_id`, `gate_path`, `source_path` and current `gate_generation`. The UI accepts it only from the selected EOS endpoint and only when gate/source/revision match the current IsOS selection. The browser does not receive EGIA's private grant or endpoint. A legacy `{type:"subscribed"}` response cannot establish Q01 evidence; the panel remains at **no new frame** with a visible rejection diagnostic until an attested subscription arrives.

Each Q01 binary frame uses EOS's little-endian `u32` metadata length, at most 4096 UTF-8 JSON metadata bytes, and at most 8 MiB JPEG bytes. The UI rejects zero/oversized/truncated metadata, malformed JSON, invalid dimensions, invalid JPEG SOI/EOI, an overlarge JPEG, and a `jpeg_sha256` mismatch computed over the exact received JPEG bytes. It requires `graph_revision` (64 lowercase saved whole-graph hex), `projection_revision` (64 lowercase EOS projection hex), `runtime_stream_id` (UUID), `source_path` (canonical camera path), `source_frame_id` (nonblank EOS ID), `gate_path` (selected gate), `gate_generation` (positive unsigned 64-bit), `render` (selected width/quality), and `jpeg_sha256` (64 lowercase hex). Optional `sequence` and `timestamp_unix_ms` may be absent. The same delivery is identified by `(graph_revision, runtime_stream_id, gate_path, gate_generation)`; source sequence alone is insufficient. Different render parameters can produce different JPEG digests for one delivery, so Q01 byte equality with EGIA requires the same selected render values and verified digests.

The UI accepts only a generation strictly greater than the last displayed generation in the current attested stream. It never resets that baseline on a mere binary frame. A new stream requires a fresh selected-endpoint subscription handshake, and a new IsOS run requires a fresh process-status read and subscription. On Stop intent, run/revision/selection change, socket close, hide/unmount, or loss of process status, it revokes the display generation token, closes the socket, removes the current JPEG, and shows `stopped`, `stale`, `disconnected` or `evidence unavailable` as appropriate. A late decode or digest promise cannot repaint after that token changes. A malformed, duplicate, older, wrong-revision, wrong-source, wrong-gate or wrong-stream frame is rejected and leaves the displayed generation unchanged; it shows an explicit **frame rejected** diagnostic with a stable local reason, not an empty or successful frame. `no new frame` while the stream is healthy remains distinct from rejection, disconnect, and missing bound evidence. EOS must not send a cached frame after shutdown.

The decoder now limits metadata to 4096 bytes and validates the selected owner fields and JPEG digest before display. The panel shows selected source, gate, run, stream, generation, digest, subscription cap, delivered FPS, and locally observed skipped generations. It does not claim EOS router-wide cap or gap totals. Focused tests cover positive and negative frame decisions plus a mounted Stop/late-digest boundary. A selected-pin browser replay remains Q01 qualification work. The UI has no image upload, prompt, or actuator path from this display.

## Public browser endpoint

IsosUI connects only to the existing **public loopback TCP** `WS /api/eos/v2/vision/ws` on the selected EOS browser bridge origin; its `GET /api/eos/v2/vision/gates` supplies the EOS projection `revision`. It never opens `eos-vision-owner.sock` or EGIA's inspection UDS, and receives neither the EOS subscriber grant nor the separate EGIA inspection grant. The IsOS `process-status.vision_evidence` projection provides only the selected gate, source, projection revision, fixed `{max_width_px:1280,jpeg_quality:80}` and `target_fps:30`, alongside current run and active saved-graph revision; no endpoint or grant path appears there. The UI sends exactly these render/rate values in the public `subscribe`. A public `subscribed` attestation with `gate_generation:0` is a ready stream with **no frame yet**, not an image. Wrong gate/source, saved/projection revision, stream or later generation is rejected before replacing the displayed JPEG. The browser path retains Host and Origin checks; an `Authorization` header or owner grant on it is invalid. Stop and run changes clear the displayed frame even if the old public socket remains briefly readable.
