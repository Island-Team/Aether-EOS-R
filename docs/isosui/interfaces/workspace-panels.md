# U03 workspace panel contract

IsosUI owns browser-local layout only. The persisted key is `isosui:workspace:v1:<robot-id>` and contains `{version: 1, panels}`. Each of `control`, `monitor`, `vision`, and `logs` has `open`, `collapsed`, `docked` booleans and finite pixel `x`, `y`, `width`, `height`, `z` numbers. Invalid or older values reset to defaults. Load and viewport resize clamp geometry. The robot ID comes from IsOS's saved graph. Layout never changes graph bytes or grants command authority.

One persistent EOS workbench owns the live control, monitor and Vision projections across Graph/EOS navigation. One Logs consumer owns the P07 cursor. Dock/collapse keeps panel content mounted; close hides Control while keeping its current-run command record in memory and unmounts Logs so reopen must recheck IsOS status and current scope. A hidden or collapsed Monitor, Vision or Logs panel does not poll or stream; the control panel pauses automatic result reads while hidden. All data remains fenced by owner run and active revision.

The fixed workspace strip displays connection state and active revision from IsOS and always exposes IsOS Stop. Stop intent fences Invoke and result follow-up synchronously across panels and pages. Only IsOS's typed Stop response can label Stop confirmed; unknown or failed Stop remains visible as such. EOS owner results remain separate from Stop outcome. The historical [M4 affected-boundary replay](https://github.com/Island-Team/Island-eos/blob/refactor%28v2%29/runtime-main/docs/island/m4-affected-replay.md) passed the selected A03 negative and supervised mission paths; its IsOS pin did not support same-run EGIA child replacement. Later [Q03/Q04 evidence](../q03-evidence.md) uses separate input pins.

**Stop fence release.** An intent is global while pending, regardless of which page supplied a run ID. Overlapping Stop requests remain pending until every owner response arrives. After IsOS returns a Stop outcome, the workspace makes fresh owner status reads. A known running run releases the fence only if its run ID differs from the recorded caller, workspace, or typed terminal run, or a stopped/no-run state was observed first. An unavailable identity, a still-running recorded run, or a pending Stop cannot release it. If no old identity is known and no stopped transition or terminal run ID is available, the UI keeps the fence until it can establish a new run safely. A narrow viewport forces stacked panels; Float is disabled there, while a previously floating panel can be docked.

**Vision provenance implemented:** The [Vision provenance display contract](vision-provenance.md) adds a run/revision/stream/generation fence and same-byte digest verification to the Vision panel. Hiding or stopping the panel clears its current evidence and prevents late frames from repainting it. The [Q03 final-17 and Q04 final-5 replays](../q03-evidence.md) observed rendered frames on their separately pinned inputs; final-5 used a simulated hosted Origin on loopback.
