# IsOS 包管理器：当前路径与 v0.2.1 目标

[English](../../../docs/isos/design/package-manager-target.md) · [当前软件包准入](../../../docs/isos/design/packages.md) · [发布契约](../../../docs/isos/interfaces/packages/release.md) · [合并计划](../../../ARCHITECTURE-QUESTIONS.md)

**状态：**统一 IsOS v0.2.1 的设计。第一节描述现有代码，其余章节规定目标。目标步骤不代表已经实现。软件包、图、节点配置、进程、模拟器及 IsOS 产品版本相互独立。

## 当前包管理器：已实现的路径

```text
已批准的 Island-port 目录 ── 精确 {id, version} 清单
                                               │
已审核的本地清单 ────────────────────────────────┤
                                               ▼
                                  选择主机资产／本地包
                                               ▼
                            校验 SHA、大小、路径、载荷、适配器
                                               ▼
                       本地仓库＋收据＋发布清单＋类型侧车文件
                                               ▼
                  图中精确固定版本 → Verify → Validate/Apply → Run/Restart
```

IsOS 目前通过 `https://www.os-island.com/api/packages/v1` 查询 Island-port 目录并获取指定版本的发布元数据。`isos pkg install` 从发布清单选择匹配平台的资产，通过 HTTPS 下载，检查声明的大小与 SHA-256，拒绝不安全的归档路径和符号链接，验证声明的可执行文件、资源和适配器库，然后以原子方式发布到本地仓库。`isos pkg link` 接受明确指定的本地包和清单，记录文件指纹；字节发生变化后必须重新链接。本地仓库位于用户数据目录的 `packages/<namespace>/<name>/<version>`，包含 schema-2 收据、规范化的 `release.json`，以及可选的生成文件 `node-types.json`。搜索结果本身不会触发安装或启动。

图节点以精确 `{id, version}` 选择软件包。在图准入及 Run/Restart 时，IsOS 重新检查收据、发布清单哈希、完整载荷哈希、侧车文件、注册节点类型、资源 ID、所有者及生命周期能力。若保存的图或当前运行状态仍引用该精确版本，则拒绝删除。软件包 ID 和可执行文件名不决定特殊的运行时行为。EOS 拥有硬件适配器和命令准入；经 IsOS 验证的软件包声明不会自动获得执行器控制通道。目前仅针对已发布的 MuJoCo 0.1.1 schema-4 清单提供摘要锁定的导入适配器；其他 schema-4 软件包会被拒绝。

当前 CLI 提供搜索、详情、安装、链接、列出、验证、移除、节点集预览、发布与上传。当前 HTTP API 在 `/api/isos/v1` 下提供列出、安装、链接与链接预览。已发布的软件包契约是 `isos.package@v1`，清单 schema 为 `0.1.0`。目前**尚无通用依赖求解器、事务性软件包升级、离线注册表缓存、已签名的注册表信任根或基于 GitHub 的 IsOS 自更新流程**。当前的 `version check` 和 HTTP 版本路由报告本地身份／就绪状态，并不检查最新发布版本。

## 目标所有权图

| 所有者 | 可以执行 | 不得执行 |
| --- | --- | --- |
| IsOS 包管理器 | 验证注册表元数据、清单、资产、本地收据、兼容性、图引用和暂存更新；维护已安装清单与审计证据。 | 将不透明硬件载荷解释为授权、启动未经准入的进程、暗中修改已应用的图。 |
| IsOS 图管理器 | 固定精确的软件包发布版本与节点／配置版本；以原子方式验证和应用修订。 | 在 Run 时解析 `latest`、自动改写用户图设置，或绕过软件包验证。 |
| EOS | 验证 EOS 所有的包贡献，按需监管模拟器／后端子进程，并通过 Dispatcher 控制全部执行器准入与 Stop。 | 仅凭软件包元数据授予设备权限，或创建第二条执行器通道。 |
| EI | 验证 EI 所有的扩展，并按其生命周期契约运行智能工作负载。 | 直接写入已应用的图或执行器。 |
| 公共注册表 | 为公共软件包发布经过审核、无敏感信息的发布元数据与不可变资产。 | 保存真实硬件设置、密钥、标定、设备身份或私有调试证据。 |
| 私有注册表／`isos-p` | 在访问控制下保存硬件软件包与设置证据，并采用相同的软件包契约和验证规则。 | 向公共索引、源码快照、日志或发行说明泄露私有元数据。 |
| IsosUI | 通过 IsOS API 呈现搜索、已安装清单、计划、验证与更新同意。 | 绕过 IsOS 独立下载、安装或启动软件包。 |

`isos-p` 是私有**源码**仓库。私有软件包注册表是单独受控的分发渠道；源码仓库本身不会自动成为安全的软件包注册表。注册表凭据保存在用户凭据存储中，绝不写入图文件或受版本控制的配置。

## 版本与支持映射

纳入版本控制的 `config/version-support.toml` 是对应 IsOS 构建的本地兼容性依据。CI 根据实际注册契约生成或校验它。它列出产品版本、接受的图格式、精确的软件包清单身份、节点／配置版本、IsOS 与所有者进程之间的契约、EOS/EI 接口契约以及软件包约束。无论在线或离线，运行时都使用该映射。注册表元数据可以提示更新，却不能扩大已安装二进制文件的兼容范围。

**当前实现阶段：**内置映射通过命令行与 HTTP 版本接口报告产品、目标图格式、HTTP、软件包及固定的 MuJoCo 身份。软件包清单准入现从映射读取契约和 schema，已发布 MuJoCo 资产的精确固定摘要也来自映射。IsOS 设置身份现要求 EOS／EI 产品版本精确为 0.2.1，才允许启动并报告就绪。Apply／Run 的图及其他所有者检查仍使用现有验证器；更广的准入集成及 CI 一致性检查仍属于目标工作。

| 身份 | 示例／当前值 | 目标检查 |
| --- | --- | --- |
| IsOS 产品 | `0.2.1` | 用于显示、来源追溯和版本选择；不能代替接口检查。 |
| 图格式 | `0.2.0` | 精确匹配接受的格式及 `isos` 核心；迁移必须显式执行。 |
| 注册类型／配置 | `isos.<layer>.<name>@v0.2` | 精确检查类型 ID、位置、设置、端口、能力及所有者。 |
| 软件包清单 | 当前为 `isos.package@v1`、schema `0.1.0` | 导入器精确匹配所接受的契约／schema；运行时仓库存放规范化的当前记录。 |
| 软件包发布 | `{id, version, source commit, asset digest}` | 精确固定不可变版本及匹配主机的资产。 |
| EOS/EI／进程通信 | 独立版本化的契约 | 就绪前握手确认精确支持的契约集合；拒绝不匹配及过期修订／代次。 |
| MuJoCo | `island/mujoco-sim@0.1.1` | 精确核验已批准清单与资产摘要，以及模拟器协议和场景声明。 |

外部软件包在支持映射中的记录包含接受的清单身份、所有者、所需进程／适配器契约、平台限制；只有所有者测试过版本范围时才记录最低／最高支持版本，并可附精确摘要白名单。活动图优先使用精确版本和摘要。软件包的 SemVer 不代表通信协议兼容。`isos version check` 返回 `compatible`、`migration_required` 或 `unsupported`，并指出每个失败字段与支持值。它绝不暗中导入旧数据或改变正在运行的实例。

## 注册表模型

在 v0.2.1 中，**Island-port 继续作为公共软件包元数据目录**，**GitHub 承载公开的 IsOS 产品发布以及适合公开的已批准软件包资产**，真实硬件软件包使用独立的认证私有渠道。注册表客户端接口与托管地址解耦。一个客户端契约支持两个软件包渠道：

1. **公共渠道：**经过审核、不可变的软件包发布索引，提供搜索／发现、精确发布元数据、资产摘要／大小／平台、契约声明、发布者来源、审核状态及撤销状态。可用时允许匿名读取；作者发布须认证并接受审核。
2. **私有渠道：**用于真实硬件软件包、驱动构建、依赖标定的适配器及现场证据的访问控制索引。登录只允许发现和下载；软件包存在不等于获得设备控制权。公共搜索响应不得泄露私有软件包名称或元数据。

注册表条目是元数据，不是可执行信任。目标信任链由固定的注册表信任根、带签名及过期时间的索引／发布元数据、按内容寻址的资产组成。CI 与客户端验证签名、新鲜度、防回滚、资产摘要，以及发布者／审核策略。在该信任链实现前，现有的精确批准目录与摘要验证仍是已实现的边界；不得声称已有签名。离线缓存索引仅在其签名有效期内可用于授权。过期缓存可以显示清单，但不能批准新安装。若最近一次可信快照中的策略未撤销某个精确固定版本，完整本地验证后，该已安装版本仍可离线使用；实现前须明确定义撤销信息的有效期限。

**发布流程：**作者构建软件包与清单 → 本地 `pkg validate` 检查 schema、有界路径、精确资产、节点贡献、所有者契约及平台声明 → 运行所有者测试 → 向公共或私有审核渠道提交元数据与资产 → 审核者检查公开风险、许可证、来源、测试证据及摘要 → 注册表签名并发布不可变版本 → 客户端可以发现。修正必须创建新版本，不得覆写已有 `{id,version}` 对应的字节。撤销会阻止新安装并给出有限范围内的原因；除非有明确安全策略，否则不会暗中删除已安装软件包或停止运行中的执行器。

## 操作员工作流图

```text
发现／本地来源
        │
        ▼
查看精确发布版本、渠道、契约、平台及来源
        │
        ▼
规划：对照本地支持映射、图固定版本、所有者能力及依赖
        │
        ├── 不兼容 → 指明精确字段；不修改状态
        ▼
同意安装／链接／更新
        │
        ▼
下载至暂存区 → 验证注册表策略、清单、摘要及安全目录树
        │
        ├── 失败 → 删除暂存区；已安装内容／图／运行状态不变
        ▼
以原子方式发布不可变软件包版本与收据
        │
        ▼
验证拟议图修订及各所有者的投影
        │
        ├── 失败 → 软件包保留安装但不选用；运行状态不变
        ▼
操作员 Apply 精确修订 → 就绪预检 → Run/Restart
        │
        ▼
监控；安全 Stop；显式移除未被引用的旧软件包
```

| 操作 | 必需输入 | 状态影响 | 拒绝行为 |
| --- | --- | --- | --- |
| 搜索／详情 | 渠道、查询或精确 ID／版本 | 只读。在线结果仅供发现，不代表批准。 | 离线／认证失败时报告状态；本地清单仍可用。 |
| 安装规划 | 精确发布版本、平台、本地支持映射 | 只读的兼容性和依赖计划。 | 精确指出不支持的契约、缺失依赖、平台或策略路径。 |
| 安装 | 精确发布版本及操作员同意 | 发布不可变的已验证仓库版本；图／运行状态不变。 | 删除暂存区，保留此前版本。 |
| 链接（开发／私有） | 精确本地清单及软件包 | 记录已验证的本地指纹；图／运行状态不变。 | 字节变化须显式重新链接；不会自动信任本地路径。 |
| 验证 | 精确已安装固定版本或全部已选版本 | 只读；检查收据、清单、载荷、侧车文件及适配器文件哈希。 | 以有限诊断安全拒绝；Run 期间不尝试修复。 |
| 选择／Apply | 精确图固定版本及修订 | 所有所有者验证后，原子修改期望图。 | 保存的字节／修订及活动运行状态不变。 |
| Run／Restart | 已应用修订、已验证的精确固定版本及所有者就绪 | 启动绑定修订的代次；EOS 控制执行器安全。 | 不返回部分健康结果；遵守安全 Stop／不确定结果规则。 |
| 软件包更新规划 | 现有固定版本、拟议的新精确版本、依赖与图迁移计划 | 只读；展示操作员可见的差异和回滚前提。 | 不兼容的软件包不能暂存为活动替代版本。 |
| 提交软件包更新 | 显式同意、已验证的暂存版本、已接受的图迁移 | 原子修改图修订，然后受控重启；保留旧包供回滚。 | 尽可能保留旧固定版本／运行状态；Stop 结果不确定时禁止重启。 |
| 移除 | 精确已安装固定版本 | 仅当保存／活动／恢复状态均无引用时删除。 | 拒绝移除被引用的软件包并列出各引用。 |

已应用的图中不允许出现 `latest`。若支持依赖，其精确版本必须构成有界无环图；求解器可以*建议*固定版本，却不能暗中选择。v0.2.1 可以拒绝未声明的传递依赖，而不是交付不完整的求解器。更新采用并存暂存方式，以便回滚时仍有已验证的旧包和旧图修订。执行器 Stop 结果不确定时绝不自动回滚。

## IsOS 产品更新与软件包更新

联网时，`isos update check` 将已安装的 IsOS 产品版本与公共 `Island-Team/isos` 的最新**已发布**版本比较。IsosUI 提供相同的显式检查操作；两者都不在启动时自动执行在线检查。如果 GitHub 访问需要登录，则提示登录 GitHub；启动、Run 与本地兼容性检查不依赖登录。离线或未认证时，报告 `online status unknown` 并检查本地支持映射。不能因为 GitHub 上存在发布版本，就推断本地图、软件包或通信契约兼容。

`isos update/upgrade` 展示精确的目标发布版本、发行说明、支持版本映射、图／软件包迁移影响、资产摘要及回滚限制。下载或安装前征求同意。验证发布来源与资产字节，暂存新的 IsOS 安装，执行兼容性预检，安全停止子进程，原子切换并检查就绪状态。新代次健康前保留旧安装及数据快照。服务器启动时不自动更新自身或外部软件包。除非 v0.2.1 已通过全部 Stop、回滚及签名测试，否则自动切换属于后续实现阶段。

## 硬件信息与公开审查

所有**真实硬件专属**信息放在 `isos-p` 或限制更严格的私有存储中：机器人 ID／序列号、标定、设备配置、驱动端点与局域网拓扑、凭据，以及可识别实际部署的现场日志、影像和调试轨迹。公共 `isos` 可以包含通用硬件接口、合成测试数据、模拟适配器、脱敏示例，以及不使用真实设备身份的可复现测试。公共快照流程必须扫描受版本控制的源码、每个新提交、归档、生成绑定、文档和测试数据；每条发现由对应所有者审核。两个仓库的可复用示例均不得使用用户绝对路径或真实部署配置。提供 `.example` 文件和文档化的默认值，活动设置文件应被 Git 忽略。

## 实现阶段与验收

1. **当前路径清单：**记录实际目录端点、清单／收据 schema、全部固定版本位置、启动所有权及剩余旧版导入。保持现有精确版本验证通过。
2. **支持映射：**增加版本化文件／schema、解析器、与注册契约的一致性检查、本地 CLI／HTTP 状态、失配诊断及离线测试。
3. **注册表边界：**区分公共／私有渠道、受认证的私有发现、签名元数据与缓存策略、不可变发布、撤销及公开审查。不得将注册表登录绑定到 IsOS 启动。
4. **软件包规划／更新：**精确依赖和兼容性计划、并存暂存、操作员同意、图修订更新、安全重启、回滚及不确定结果测试。
5. **产品更新：**可选的 GitHub 检查和登录、发布验证、同意、暂存、安全切换、回滚及离线回退。
6. **资格验证：**空白用户目录安装／链接 → 图 Validate/Apply → 所有者就绪 → 相机／已准入控制 → 故障／重启 → Stop；测试载荷变化、过期索引、错误签名／摘要／平台／契约、缓存到期、版本撤销、所有者失败及 Stop 结果不确定。完整日志保存至 `logs/test/<run-id>/`。

**剩余实现选择：**确定签名注册表信任根和撤销信息新鲜度窗口，并选择精确的 IsOS 更新资产及回滚打包形式。独立的一次性导入器处理受支持的旧图／软件包数据；IsosUI 仅在用户显式操作时在线检查。在经过审核的契约迁移前，这些选择不改变当前精确版本安装行为。
