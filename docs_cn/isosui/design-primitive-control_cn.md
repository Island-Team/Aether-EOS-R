# U04 实现设计与证据

[English](../../docs/isosui/design-primitive-control.md) · [所有者接口](interfaces/primitive-control_cn.md)

R07 结果客户端继续作为唯一浏览器命令路径。U04 将单个模拟底盘卡扩展为每个精确活动 `@v0.1` 底盘／机械臂绑定各一张卡。纯绑定解析器在呈现前验证唯一目标和声明的模式。组件在 EOS 时间读取与提交前后重新检查 IsOS 图／运行身份，并沿用现有的关联结果状态机。`Failed` 是所有者终态结果，浏览器传输丢失则显示不可用。Stop 独立调用 IsOS，并在等待响应前对当前运行的所有卡片设置围栏，取消其他卡片的结果读取并丢弃迟到回复。不会暴露旧版图定义技能序列。

图节点在 portal 中呈现信息卡，使其浮于重叠 React Flow 节点之上。悬停、聚焦和触摸信息按钮打开卡片；Escape 和关闭按钮退出。卡片非模态，打开与视口尺寸变化时限制位置；所有者读取不可用时不声称实时健康。端口单位来自节点目录数据模式。portal 中的信息控件使用 `nodrag` 与 `nowheel`。可见的已打开卡片每两秒读取 EOS，失败或超过五秒的样本标为过期。

验证：`npm ci --no-audit --no-fund`；`npm test`（144 个测试通过，包括精确底盘／机械臂绑定、歧义、过期运行、结果跟进、Stop 失败及视口限制）；`npm run typecheck`；`npm run build`；`git diff --check`。完整日志位于本地 `logs/test/20261102-u04-primitive-control/`。使用受支持的 Node 22.23.4／npm 10.9.9。浏览器视觉检查与 M5 洁净主目录重放仍属独立验收门槛。

## 工作台刷新验收修复

所选归属方目录读取可能超过工作台五秒间隔。此前每次定时器触发都会使正在进行的响应失效，导致图、状态和控件一直不显示。现在同一时间只执行一次刷新，期间的定时触发会跳过。手动 **刷新** 立即禁用 Invoke、使旧请求失效，并将重复点击合并为一次后续读取。只有图／目录／状态与 EOS 发现结果一致时，后续读取才发布；失败或修订不匹配时保持只读。新修订或运行会清除旧发现／健康数据，并重启硬件轮询，避免迟到的旧运行样本重新填入。挂载代数与最新回调引用确保卸载后的回复不会发布，父组件回调变化也不会重新启动读取。

Node 22.23.4／npm 10.9.9 验证：`npm ci --no-audit --no-fund`；`npm test`（39 个文件、179 个测试，包括八个定时器延迟、手动队列、修订不匹配、新运行健康状态、卸载／发现、回调身份及 StrictMode 用例）；`npm run build`（类型检查、本地与托管构建及清单）；`git diff --check`。完整测试与构建输出及独立设计审查保存在被忽略的 `logs/test/20261102-workbench-refresh/`。最终浏览器重放属于 M4 验收门槛。

## Q01 命令截止时间顺序

一次选定版本的首次使用重放发现：浏览器读取 EOS 单调时间后、发送四秒截止时间的类型化命令前，IsOS 的进程状态读取耗时 13.9 秒。请求到达准入时已过期，界面正确显示为不可用。发送端现先完成最后一次 IsOS 状态围栏，再读取 EOS 时间，并在单次发送前立即检查最新的本地运行／修订、绑定、编辑、Stop 和取消状态。本地状态若在等待中改变，就取消发送；过期或结果不确定的命令 ID 不会重试。所有者接口契约与延迟读取的挂载测试覆盖这一顺序。
