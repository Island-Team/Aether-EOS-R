# Q01 EOS Vision 所有者首次使用

[English](../../../docs/eos/develop/vision-provenance.md) · [Vision 接口](../interfaces/vision_cn.md) · [Q01 计划](../../island/implementation-todo_cn.md)

本指南说明 IsOS 选定相机至 EGIA 证据绑定中的 EOS 部分。IsOS 拥有已保存图、运行目录、选定 gate、验证文件与授权密钥。EOS 运行时只读已应用投影；HTTP 桥接器保留公共回环 Vision 端点，同时增加仅供所有者使用的 Unix listener。

1. 在 IsOS `[vision_evidence].gate_path` 选定一个活动 `eos.interface.camera_gate@v0.1`。来源须是已注册的 `eos.hardware.camera@v0.1`，并有已准入的 EOS 本地 `frame:camera_frame` 路由。验证并应用保存图。图作者不能写 `service_bridge` 边。
2. 用 `aether-runtime --capabilities` 与 `aether-http-bridge --capabilities` 检查选定二进制文件，须分别包含 `vision-provenance-v1` 和 `vision-owner-uds-v1`。IsOS 在替换运行中的部署前重新校验可执行文件和软件包的精确字节。
3. 通过 IsOS 启动托管 EOS。在私有运行时 socket 上发送 `{"op":"vision_attest","gate_path":"<选定 gate>"}`，可得到 IsOS 保存图 `active_revision`、EOS `projection_revision`、部署 `run_id`、新的 `runtime_stream_id`、来源和 gate 路径，以及首帧前的 `gate_generation:0`。gate 不健康或 EOS 停止时返回不可用。独立运行的 EOS 不能声称托管来源。
4. IsOS 以公共 `--listen`、EOS 私有 `--socket`、`--run-id` 和 `--owner-vision-socket <endpoint-dir>/eos-vision-owner.sock` 启动同一个 `aether-http-bridge` 进程。只给 bridge 传入 `AETHER_BRIDGE_VISION_VERIFIER_FILE`。验证文件与 socket 位于同一个 0700 私有端点目录，文件模式 0600，包含解码后 32 字节 EGIA Vision 密钥的 SHA-256，不包含密钥本身。IsOS 将授权文件和绑定保留在控制授权运行目录。所有者 listener 模式为 0600，仅接受相同 UID 的 UDS 对端、`Host: localhost`、无 Origin 或 Sec-Fetch 头，以及准确的 bearer 密钥。公共 TCP 请求携带 Authorization 时被拒绝。
   托管回放从控制授权运行目录读取 `egia/vision-binding.json` 和授权文件，并连接绑定中的绝对路径 `eos_endpoint.path`。其父目录是 IsOS 选定的 `run/v/<32 位十六进制>` 目录；EGIA 检查 socket 和可选的一次性旧帧测试 socket 从同一目录派生。连接前，回放会对照部署名和 run ID 校验端点摘要。
5. EGIA 订阅方请求 `GET /api/eos/v2/vision/owner-ws`，随后发送一条 masked `subscribe` 帧，包含选定 gate、EOS 投影版本和 `target_fps:30`、`max_width_px:1280`、`jpeg_quality:80`。重连可同时传入 `after_generation` 与 `after_runtime_stream_id`；旧 stream 被拒绝。成功的 `subscribed` 文本帧先于任何二进制帧。元数据和 JPEG 分别限制在 4096 字节与 8 MiB。验证交付身份 `(graph_revision,runtime_stream_id,gate_path,gate_generation)`、源帧 ID，以及收到的精确 JPEG 字节的 SHA-256。浏览器与 EGIA 只有在请求相同固定渲染时才得到同一 JPEG。
6. 用 `route_status` 查看 `cap_wait_count`、`replaced_count` 和 `gap_count`。通过 IsOS 停止，并确认原有执行器停止先于 MuJoCo 终止。EOS 在停止动作前封闭 Vision 发布；bridge 停止时关闭所有者订阅并删除运行 socket。每次有界轮询都会重新读取私有 verifier 和就绪证明，因此授权撤销后，已有订阅在发送下一帧 JPEG 前结束。新的 EOS 子进程更换 `runtime_stream_id`；新的 IsOS 运行还会更换 Vision 密钥。

局部检查可运行 `cargo test -p aether-http-bridge --bin aether-http-bridge`、`cargo test -p aether-runtime --test process managed_gate_attests_saved_and_projection_revisions_and_exact_jpeg` 与 `cargo fmt --all -- --check`。这些测试覆盖 EOS 边界，本身不代表跨所有者 Q01 回放已合格。所有者绑定实现后，完整选定版本回放及篡改用例记录在 Q01 验证证据中。

## 实现证据

2026-11-02，此 EOS 候选在 Linux 7.0.0-38-generic x86-64、Rust 工作区版本 `0.2.0` 上运行。完整本地输出保存在已忽略的 `logs/test/20261102-q01-vision-eos/`。在 EOS 工作树根目录执行 `python3 tests/fixtures/q01_vision_provenance/check_cases.py`、`python3 scripts/check_doc_links.py --all`、`cargo fmt --all -- --check`、`cargo clippy --workspace --all-targets -- -D warnings`、`RUST_TEST_THREADS=1 cargo test --workspace --no-fail-fast` 及 `cargo build --workspace`。局部 `cargo test -p aether-http-bridge` 和 `cargo test -p aether-runtime --test process` 覆盖所有者密钥与版本拒绝、首帧前证明、托管 gate 摘要和浏览器兼容性。默认并行工作区运行中，五个既有 `backend_child` 进程组用例相互干扰；完整串行工作区回放通过。这只是 EOS 所有者证据。在合并此主题前，仍需跨所有者选定版本 Q01 验证及独立实现审查。
