# EOS 路线图与运行时后续工作

[English](../../../todo.md)

本页是规划清单，不表示列出的能力已经实现或承诺了发布日期。当前验证基线为 NVIDIA GPU PC 与 Jetson 上原生运行的 Ubuntu 22.04/24.04。所有里程碑均须保留唯一 Dispatcher 动作释放入口和部署侧硬件限制。

## 模型库发现与热重载

**现状：** 模型 ID、能力、启用状态、端点和 adapter 来自启动配置。EOS 通过有界 worker 调用单独启动的 HTTP 或视觉 WebSocket 服务；修改目录需要重启。

**目标：** 发现并校验可部署模型定义，原子发布新目录代际，在替换 provider 前排空或拒绝进行中的调用。推理服务仍独立运行，schema 或能力不匹配时拒绝准入。

**依赖：** 版本化模型包契约、来源记录、代际所有权，以及不健康替换的回滚规则。

**完成标准：** 可在不重启 `eosd` 的情况下安装、替换、禁用和回滚模型；并发调用只观察到一个有效代际，无效包不可调用。

## 通过 pybind11 编写 Python 技能

**现状：** 可信 native ABI v2 库在启动时加载。managed 和 external skill runtime 仍是占位；EOS 不执行 Python 技能，也不热重载 native 库。

**目标：** 在进程外 skill host 中通过 pybind11 提供受能力约束的 Python API，包括类型化参数/结果、取消、SIGNAL、观察，以及经过 Dispatcher 的 primitive 调用。

**依赖：** 外部 host 协议、包准入、进程监管、稳定的 Python SDK ABI 和版本策略。

**完成标准：** 用户编写的 Python 包可以安装、发现、执行和取消；未声明能力的调用被拒绝，`eosd` 不嵌入 Python。

## 技能沙箱占位与隔离

**现状：** 内建 coroutine 技能和 native 库可信并共享 daemon 地址空间。external runtime 目录默认拒绝，尚不启动子进程。

**目标：** 为具身技能测试定义未来沙箱边界，明确资源、文件系统、网络、设备、时间和终止策略。首步只提供契约和惰性集成点，不宣称已有隔离。

**依赖：** 外部 skill host 监管与能力范围内的 IPC；隔离技术在威胁模型及平台评审后确定。

**完成标准：** 占位有明确的准入/生命周期契约，反向测试证明未配置的沙箱或外部技能不能执行；后续隔离有可测的验证矩阵。

## IPC 与共享内存优化

**现状：** 内建技能 IPC 为有界、进程内 JSON mailbox；模拟器 IPC 使用独立本地 socket。当前没有通用跨 runtime 传输或共享内存传输。

**目标：** 为外部 host 加入有界协议，并为大帧或 tensor 提供可选共享内存传输，同时保留消息身份、所有权、截止时间、取消及隐私控制。小型控制消息使用简单的帧协议。

**依赖：** 外部 host 生命周期、payload 生存期规则、背压指标及代表性 Jetson/PC 工作负载的基准数据。

**完成标准：** 崩溃、超时、过期 handle 和背压有正确性测试；基准证明减少拷贝与延迟，且不改变公开技能语义。

## 后端生态与 ROS 2

**现状：** 每个进程的一个已准入绑定拥有一台机器人。现有 demo、主机 ALSA/V4L2、原生 `aplay`、可选 ROS 2。ROS 2 在构建时选择；站点 graph bridge 与物理安全限制由部署侧拥有。

**目标：** 验证更多标准 ROS 2 设备映射和可复用适配器包，同时将端点、坐标系、关节和控制器细节留在站点绑定中。每个适配器应提供兼容性与健康状态证据。

**依赖：** 契约测试、代表性 ROS graph、部署侧驱动验证。

**完成标准：** 新后端通过准入、feed、命令、stop/estop、断连与恢复测试，且不改变 northbound 契约或绕开 Dispatcher。

## 动态图与可视化 WebUI

**现状：** 硬件与模型绑定在启动时确定；workflow 以 ActionList 提交。模拟器有单独的 WebUI API，但没有连接模型、技能、primitive 和设备的可视化图编辑器。

**目标：** 提供版本化图定义与 WebUI，连接模型输出、技能调用、primitive 绑定和硬件观察；激活前显示类型、单位、数据流、健康状态和被拒绝的边。

**依赖：** 稳定的目录/发现 API、模型代际、技能能力，以及遵守 Dispatcher 入口的图校验器。

**完成标准：** 操作员可组合、校验、保存、加载和观察图；无效或不安全的连接被拒绝，可视化执行状态与 runtime 事件一致。

## 端到端与多模型推理

**现状：** EOS 通过有界 worker 分别调用已配置模型；摄像头增强可独立运行，但尚无统一多模型调度器或端到端模型执行契约。

**目标：** 支持组合式感知到动作模型与协调的多模型推理，明确资源预算、batch/placement 策略、新鲜度、来源记录和现有命令入口的安全检查。

**依赖：** 动态模型目录、图类型、实测 GPU/CPU/内存预算，以及取消和背压行为。

**完成标准：** 代表性的串联和并行模型负载在合格的 PC 与 Jetson 上满足公开的延迟和内存预算，失败确定且不直接绕过动作入口。

## 多操作系统支持

**现状：** 构建与部署基线为 NVIDIA GPU PC 和 Jetson 上的原生 Ubuntu 22.04/24.04；可选 ROS 2 版本匹配宿主发行版。不支持从 x86 交叉编译 ARM64。

**目标：** 审计平台依赖，根据构建、驱动、ROS、IPC、打包及支持成本选择下一个 OS 目标，然后增加合格的构建与部署路径。

**依赖：** 可移植性清单、目标选择记录、CI runner 或代表性硬件，以及适配器能力矩阵。

**完成标准：** 有证据支持的目标选择、在 CI 中构建和测试可移植核心、部署文档明确哪些硬件及可选适配器已验证。在选择前不承诺额外 OS。

## 跨领域运行时后续工作

- 为跨 `eosd` 重启的技能执行增加持久恢复与回放；诊断 journald 输出不是可恢复的 manager 状态。
- 为未知物理结果定义重启安全的重试策略；结果模糊的动作释放后绝不隐式重试。
- 为忽略协作式取消的 callback 增加可抢占隔离；只有部署需求明确时才增加调度优先级。
- 规定目录分页、命名空间、兼容范围、部署限制和可验证的包来源/加载历史。
- 用设备健康、新鲜度、watchdog 和 lease 策略强化 Dispatcher 准入，不建立第二个动作入口。
- 为网络部署定义已认证的 Agent 访问、授权、租户隔离和安全级审计要求。
