# v2 分发树（开发中）

[English](../../../../docs/eos/design/runtime/dispatcher.md) · [硬件设计](hardware_cn.md) · [字段接口](../../interfaces/hardware_cn.md)

## 地址与职责

分发层用稳定地址为每个 core 的节点提供唯一执行路径。层级由统一的 `1.0.0` 节点 profile 声明，为 `core → layer → group → node`；首个实现的硬件路径是 `cores/eos/layers/hardware/groups/{camera,base,manipulator}/nodes/{node_id}`。同一 profile 可以描述其他 layer 和 core 的软件节点。EOS 是实际 core；EGIA 预留为同级 core，不能默认访问 EOS 设备。所有硬件节点显示 `status`、`health`，并只显示自身支持的 `observation`、`movement`、`safety` 接口。

分发层是独立于 HAL 的 Rust 模块。发现操作读取由已校验节点 profile 构成的注册表快照；运动请求指定一个节点和一个类型化模式。分发层只解析该节点一次，并在交给适配器前检查 profile 声明的能力、实测健康、所需样本新鲜度、命令期限、数值限值及安全状态。适配器是物理操作的最后把关者。导航规划、轨迹生成和逆运动学不在该层。

软件包贡献的[节点类型](../../interfaces/node-contributions_cn.md)沿用同一分发器边和准入规则。`mujoco` 等 group 名用于位置和显示，硬件种类由注册类型提供。仅有软件包安全声明不能授予执行器路径；还必须存在已编译的适配器与停止实现。

## 命令生命周期

每个命令具有调用方提供的 `command_id` 和单调时钟期限。`Dispatcher::new_durable` 独占打开有界日志目录，在调用适配器前先同步写入带版本的预留记录，再写入 `releasing` 记录。重复 ID 返回已保存结果；相同 ID 对应不同命令时拒绝。重启后，未完成记录转为 `outcome_unknown`，绝不自动再次下发。损坏或过大的记录阻止启动。内存构造函数只用于测试与进程内原型；未来 Rust 守护进程必须使用持久构造函数。释放前日志写入失败则拒绝命令；释放后终态写入失败则保留不确定结果。

急停先锁存进程安全状态，再调用各执行器独立的停止方法。分发层不再跨可能阻塞的适配器调用持有释放锁。适配器必须在物理写入边界锁存停止，使延迟的提交无法在停止后重新执行；CXX mock 实现并测试了该规则。mock 测试证明提交阻塞时停止仍能返回，但真实控制器的停止延迟与独立速度看门狗仍须在切换前测量。读取或样本校验失败会使该节点的 Rust 健康状态降级；只有 `refresh_node` 的有效且新鲜的探测才能清除故障。健康、安全和物理停止错误分别可见。

## 与现有运行时的关系和验证

这棵树是 v2 基础，不等同于当前 C++ `Dispatcher::ExecuteCommand` 行为。工作流和技能在明确切换前继续使用原有传输与 C++ 准入层，之后迁移到 v2 节点 API 和注册表。迁移期间，每个节点只能有一个有效的执行所有者，不能让新旧分发器同时对同一设备释放动作。

用假 HAL 注册表测试精确路径解析、接口发现和节点隔离。集成测试覆盖正常运动、过期观测、限值、过期命令、跨重启重复 ID 重放、损坏日志拒绝、健康降级与恢复、释放前取消以及 mock 释放阻塞时的急停。真实硬件停止延迟、控制器执行的速度租约到期和部署中的 ROS 2 图仍是正式切换前的验收用例。可复现命令写入[开发指南](../../develop/hardware_cn.md)，完整输出放在 `logs/test/<run-id>/`。
