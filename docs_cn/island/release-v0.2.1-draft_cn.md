# IsOS 0.2.1 发布说明草稿

**状态：仅供准备，2026-11-06。不得创建标签或发布此版本。**

IsOS（Island OS）把管理器、EI（Embodied Intelligence，原 EGIA）、EOS（Embodied OS）和 IsosUI 工作台整合到一个源码仓库和一个 `isos` 图核心。EI 与 EOS 仍按生命周期和安全边界运行在独立进程中。MuJoCo 仍是外部已验证软件包 `island/mujoco-sim@0.1.1`。

## 操作变化

- 新图格式为 `0.2.0`，只有 `isos` 核心。管理器保留原层；EOS 使用 `eos_*` 层，EI 使用 `ei_*` 层，浏览器节点使用 `ui` 层。
- 新类型标识采用 `isos.<layer>.<name>@v0.2`。图、HTTP、套接字、软件包、protobuf 和模拟器版本分别管理。
- 产品名称改为 EI；原 `egia` 命令和 Python 导入作为 0.2.1 的兼容别名保留。
- 旧 `0.1.0` 图可只读查看。迁移应先预览完整候选图，对未知或歧义映射给出准确路径，验证 EI/EOS 投影并比较已保存的修订，再原子地 Apply。在这些检查实现且验证之前，Apply 必须拒绝写入。

## 延续的 EOS 能力

已发布的 EOS 0.2.0 包括 Rust 运行时和五个启动程序、设备发现、Dispatcher 准入与结果日志、健康和能力服务、MuJoCo 子进程监护和仅供所有者使用的套接字适配器，以及浏览器结果。其[发布证据](../eos/maintenance/release_cn.md)属于旧版 EOS 的历史验证，不能直接证明统一源码树的 0.2.1 合格。

## 安装、限制和待完成检查

构建统一仓库，选择场景前验证外部 MuJoCo 软件包凭据。通过 IsOS 管理器 Validate 和 Apply 支持的图，再检查 EI 与 EOS 就绪状态。控制命令须经过 EI 安全检查和 EOS Dispatcher；Stop 应先安全停止已准入执行器，再回收模拟器子进程。最终安装命令、支持平台和验证结果须根据全新环境首次使用回放填写。

发布门槛包括：经审查的私有集成提交、公开源码提交与资源摘要、迁移成功和拒绝测试、Rust/CMake/EI/UI 检查、中英文链接检查，以及摄像头、控制、故障、重启和 Stop 的完整回放。日志保存在 `logs/test/<run-id>/`。保留 EOS 0.2.0 及旧 IsOS/IsosUI 资源，完成公开源码披露审查并验证 Island-web 固定版本后，才可另行决定是否创建 `v0.2.1` 标签和产品发布。
