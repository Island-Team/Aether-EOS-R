# IsOS 0.2.1 源码统一

[English](../../docs/island/unification-v0.2.1.md) · [架构](architecture_cn.md) · [约定](conventions.v1.3.1_cn.md)

**实施中。** 统一源码树与部分读取器已集成。全新 `0.2.0` 图的 Apply 已启用并通过 HTTP 所属进程验证；旧图迁移 Apply 与完整所属进程投影契约仍待完成。本文负责 IsOS 0.2.1 的仓库与节点图迁移，不授权创建产品标签或发布版本。公开的 EOS `0.2.0` 及其验收记录仍是独立发布的 EOS 运行时的历史证据。参见[候选验证记录](../../docs/island/verification-v0.2.1-candidate.md)。

## 所有权与节点图身份

IsOS（Island OS）是产品，也是新编写的 `0.2.0` 节点图中唯一的 core。EI（Embodied Intelligence，原 EGIA）和 EOS（Embodied OS）是该 core 内的领域，不再是独立的图 core。IsOS 拥有已保存节点图、软件包、进程和日志的权威状态。EI 拥有认知、决策和安全门。EOS 拥有硬件适配器、Dispatcher、命令结果和直接子进程 MuJoCo。IsosUI 展示所选节点图及各所有者的实时状态。运行进程可以保持分离，节点图路径不能替代显式传输或授权。

地址层级仍为 `core → layer → group → node`。新 core 键为 `isos`。已有 IsOS 管理层保留名称。EOS 的 `<layer>` 改为 `eos_<layer>`；EGIA 的 `<layer>` 改为 `ei_<layer>`。浏览器输入和显示节点使用已有的 `ui` 层。目标组内不冲突的组名和实例 ID 保持不变。新注册节点类型 ID 使用 `isos.<layer>.<name>@v0.2`。具体设置、端口和验证由所属接口页定义；本文不重复载荷契约。

公开产品版本为 `0.2.1`；新节点图格式为 `0.2.0`，新节点类型后缀为 `@v0.2`。已有 HTTP 路由、protobuf 身份、软件包描述符、仿真器套接字和 MuJoCo 软件包版本保持各自契约规定的身份，除非所有者接口明确引入带版本的新身份。`island/mujoco-sim@0.1.1` 仍是外部、经验证的软件包。只有显式的 IsOS 兼容适配器才能将已验证的旧 sidecar 映射为新节点类型，并保持精确的软件包收据；在图中写出新类型 ID 不会凭空获得可执行权限。

## 原子迁移

IsOS 读取受支持的 `0.1.0` 和旧版 `1.0.0` 图时不改动已保存字节。`0.1.0` 图在操作员主动请求迁移前只读。迁移先在内存中生成 `0.2.0` 候选图，将受支持的 `isos`、`eos`、`egia`、`isosui` 节点移入唯一的 `isos` core，并重写已知类型 ID、节点路径、引用、输入边、绑定和进程依赖，再按已选注册目录验证完整候选图。未知类型、目标路径重复、别名歧义和不受支持的跨进程传输会返回精确源路径错误，且已保存图和活动修订均不改变。只有完整验证和修订比较通过后，IsOS 才原子写入候选图以及生成的 EI/EOS 投影。原图字节和修订保留以供审计和回滚。

IsOS 将准入后的 EOS 层投影给 EOS，将 EI 层投影给 EI，两者使用同一个已保存修订。各进程在就绪前验证自己的投影和所选软件包字节。EI 安全门仍是 EI 提案的唯一出口；EOS Dispatcher 仍是唯一的执行器准入路径。即使两个端点现处于同一图 core，跨进程边仍需声明传输方式。停止时先关闭准入，EOS 在终止仿真器子进程前停止已准入的执行器，随后 IsOS 按依赖顺序回收进程。

## 仓库与发布边界

私有集成仓库为 `Island-Team/isos-p`，由 `Island-eos` 改名；公开源码仓库为 `Island-Team/isos`，待原公开 `isos` 让出名称后由 `Aether-EOS-R` 改名。私有仓库保留导入的历史和原提交到导入提交的映射收据。公开仓库采用独立历史中的已审核源码快照。IsOS、EOS、EI 和 IsosUI 源码版本均设为 `0.2.1`，但本次迁移不创建或发布 `v0.2.1`。删除旧仓库前，将历史 IsOS 和 IsosUI `v0.1.0` 资源及校验和镜像为明确标注的历史保存资源。旧 GitHub URL 仅作为历史坐标，不再是未来下载端点。

完成门槛是在合并后的源码树中从全新主目录重放首次使用：验证外部 MuJoCo 软件包，迁移并 Apply，启动 EI 和 EOS，确认就绪、相机数据和一次已准入控制结果，注入故障并重启，最后确认 Stop 和子进程回收。完整的格式、lint、单元、集成及中英文文档链接输出保存在被 Git 忽略的 `logs/test/<run-id>/`。可以准备 0.2.1 发布说明草稿，但不发布 0.2.1 标签、版本或产品资源。
