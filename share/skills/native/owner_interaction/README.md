# Owner interaction skills

This module registers three skills backed by one owner-acquisition and approach implementation:

- `interact_waving_owner@1.0.0` approaches a registered waving owner, asks one question (`您好，有什么可以帮您的`), drains prompt echo before taking a new ASR sequence baseline, waits for fresh owner speech, and deterministically restates any usable request as `好的，我来帮您<request>，我马上回来`. Common first-person request prefixes are removed, remaining first-person pronouns are made second-person, and trailing sentence punctuation is trimmed. Request text is only echoed in speech and never controls robot actions.
- `interact_fallen_owner@1.0.0` approaches a human whose canonical action is `fallen`, treating that stable target as the owner even when face identity is unavailable, announces assistance, moves the arm to the caller-configured `assistance_joint_positions_rad` pose, moves through the caller-configured `reset_joint_positions_rad` pose with `arm.movej@1.0.0` (absolute joint positions), and then calls `arm.init@1.0.0` to finish returning to the deployment initial pose. A failed assistance move reports `assistance_arm.failed`; a failed reset-intermediate move reports `assistance_arm_reset.failed`; and a failed final init reports `assistance_arm_init.failed`. Cancellation of any stage cancels the skill.
- `interact_furniture_owner@1.0.0` handles an owner whose action is `rest`. In `living_room` it approaches the owner; in `bedroom`, a lying owner is reached through the configured `bedside_waypoint_id`. It asks whether to open or close the switch, waits for fresh ASR, rejects ambiguous requests, navigates to `switch_waypoint_id`, moves the arm to `switch_joint_positions_rad`, announces the requested state, and resets with `arm.init@1.0.0`. Furniture calls require `arm_device_id`, `switch_waypoint_id`, and a six-value `switch_joint_positions_rad` array. A lying owner in `bedroom` also requires `bedside_waypoint_id` when navigation is enabled. Fallen-owner calls require `arm_device_id` and six-value `assistance_joint_positions_rad` and `reset_joint_positions_rad` arrays. These physical poses and waypoint IDs must come from deployment configuration and be qualified for the robot. For rehearsal, setting `navigation_enabled` to `false` skips the owner approach and all furniture waypoint reads and navigation, including the configured bedside and switch waypoints, while retaining the switch ASR request, arm motion, completion announcement, and `arm.init` reset.

All three skills require numeric person-box detection confidence of at least 0.4 while selecting and tracking an owner. They count the current valid snapshot toward confirming one owner, then require at most one newer matching frame within 60 seconds. Stable pose/action recognition does not wait for face identity; all scenarios track the same detection ID while accepting a registered name whenever it becomes available. They wait up to 60 seconds for horizontal centering within 10% of the image width and freeze the same frame's distance with arm joint 4. They calculate one relative approach offset that stops 0.6 m from a fallen person and 1 m in the other scenarios, then convert it once from a fresh localized base pose into an absolute map target. Owner detection continues during navigation without rewriting that target. Three fresh head-camera frames of the same supported trash class interrupt the owned navigation, play the matching announcement, and resume the exact frozen target only after both operations stop. During acquisition, transient missing owners, scenario/name flicker, low-confidence or invalid boxes, and missing distance observations are retried on newer detection frames. Once confirmed, the scenario is latched and centering follows the same owner ID without requiring a transient action or posture to remain visible. Waving and furniture retain a registered name when available. Missing owners and invalid geometry continue to be retried until the alignment window expires. After stable confirmation and centering, a recognized identity is announced by an identity-only `speaker.speak` call, followed by a separate pose/action call. If identity is unavailable, the pose/action announcement proceeds without a placeholder identity message. Detection monitoring continues during a fallen-owner approach; if an initially unidentified same ID gains a registered name, that identity is announced once after navigation and before the assistance message and arm motion. An identity known before approach is not repeated. Failure to recognize a face never blocks fallen assistance.

All schemas accept optional `room_name`: `living_room`, `kitchen`, `bedroom`, or `dining_room`. `navigation_enabled` defaults to `true`, preserving normal owner approach and furniture waypoint behavior. `speech_enabled` defaults to `true`. Setting it to `false` skips TTS and ASR while retaining identity checks, visual acquisition, approach, the fallen-owner assistance arm motion, and result reporting. This mode is intended only for integration testing when speech services are unavailable.

`vlm_fallback_enabled` defaults to `false` for deployment safety. When enabled, the waving skill uses a fallback inference only when no usable request can be extracted, and bounds it to approximately 31 seconds. Start, provider, timeout, and invalid-response failures add a result warning and speak the same safe fixed acknowledgment instead of failing the skill; cancellation still cancels the interaction.

When speech is enabled, waving and enhanced furniture interactions wait up to 60 seconds for a fresh prompted ASR response.
